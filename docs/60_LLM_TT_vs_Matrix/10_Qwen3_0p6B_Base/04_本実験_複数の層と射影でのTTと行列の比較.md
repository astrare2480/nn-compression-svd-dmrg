# 本実験：複数の層と射影でのTTと行列の比較

## このノートの役割

予備実験（layer 14 の `up_proj` だけ）で得た「TT 圧縮が行列の低ランク圧縮に負ける分の大部分は、目的関数を出力の誤差（計量つき）に変えれば埋まる」という結果が、別の層・射影・予算・ドメインでも成り立つかを、Qwen3-0.6B-Base の 42 通りで確かめた。

## 1. 何を比べたか

重み $W$ を、同じパラメータ数の近似 $\hat W$ に置き換える。良し悪しは重みの近さではなく、その層の出力の誤差で測る。入力の Gram 行列を $G$ として、相対二乗誤差を

$$
e = \frac{\|(W-\hat W)\,G^{1/2}\|_F^2}{\|W\,G^{1/2}\|_F^2}
$$

とする（検証データの入力で測る）。

| 方式 | 中身 |
|---|---|
| M1 | 普通の SVD（重みだけを見る行列） |
| M2 | 入力の Gram 行列で白色化した SVD（同じ予算・同じ目的関数での行列の最適解） |
| M3 | 普通の TT-SVD（重みだけを見る TT） |
| M3F | M3 から、重みの誤差のまま ALS を回した TT（対照） |
| M4 | 入力のチャネルごとの大きさで重みをつけた TT-SVD（補助） |
| M5 | M3 から、出力の誤差 $Q_\lambda$ を ALS で下げた TT（主役） |

M3 と M2 の差を「埋めるべき溝」とし、M5 がその何割を埋めたかを

$$
\rho = \frac{e_{M3}-e_{M5}}{e_{M3}-e_{M2}}
$$

で測る。$\rho=1$ なら M2 に追いつき、$\rho>1$ なら M2 を上回る。

**範囲**：layer 7・14・21 × q・k・v・o・gate・up・down × 予算 50%・25% の 42 セル。主な集計は、結果を見る前に決めた 34 セル（50% の k・v のようにランクが飽和に近い 6 セルと、開発に使った layer 14 の up の 2 セルを除く）。

**検証データ**：WikiText-2 validation の 59 記事（較正と同じ系統のドメイン）と、C4 validation の 128 文書（別のドメイン）。較正は WikiText-103 train の 128 系列。

## 2. 判定のしかた

記事・文書を単位とするブートストラップ（10,000 回）で区間をつけ、セルごとに次のように分類する。この規則は結果を見る前に固定した。

| 分類 | 意味 |
|---|---|
| high | $\rho \ge 0.5$ が区間で支持される |
| mid | $0.2 \le \rho < 0.5$ が支持される |
| low | $\rho < 0.2$ が支持される |
| unresolved | 区間が 0.2 か 0.5 をまたぐ |

34 セルの内訳から、次の 3 つの言明を判定する（基準は 34 の 3/4 を切り上げた 26）。

- **W**：WikiText-2 で high が 26 以上、かつ low が 0。
- **B**：WikiText-2 と C4 の両方で high のセルが 26 以上、かつどちらにも low がない。
- **F**：W が成り立ち、さらに M3F（重みの誤差のままの ALS）では溝の 2 割も埋まらないセルが 26 以上。成り立てば、改善は「反復の計算をしたこと」だけでは説明できない。

## 3. 結果

### 3.1 主な集計：W・B・F はすべて成立

| | high | mid | low | unresolved |
|---|---|---|---|---|
| WikiText-2 | 34 | 0 | 0 | 0 |
| C4 | 34 | 0 | 0 | 0 |

- $\rho$ は WikiText-2 で 0.77〜1.05（中央値 0.92）、C4 で 0.64〜0.94（中央値 0.85）。42 セルすべてで C4 のほうが低い。
- M3F の $\rho$ は −0.02〜0.22 で、33 セルで「2 割未満」が区間で支持された。
- M5 を別の $\lambda$（1e-7、1e-5）で回した 8 セルでも、M2 だけを別の $\lambda$ にした全セルでも、分類は変わらなかった。

![[assets/04_main_experiment/rho_by_cell.png]]

### 3.2 M2 を上回ったのは L21_down だけ

M5 と M2 の差 $e_{M5}-e_{M2}$ は、42 セル中 40 セルで区間ごと正だった。上回ったのは layer 21 の `down_proj`（WikiText-2 で $\rho$ = 1.01・1.05）だけで、C4 では 1 を下回った。M2 は作り直して検算している。

### 3.3 attention の出力まで見ると k・v で弱まる

射影 1 つを置き換えたときの、残差を足す前のサブ層の出力（attention なら o_proj のあと、MLP なら down_proj のあと）で同じ分類をすると、34 セル中 29 セルが high だった。high でないのはすべて k と v で、layer 21 の v では M5 の attention の出力の誤差が M3 より大きかった。MLP と q・o は両方のドメインで high。

### 3.4 言語モデルとしての性能（NLL）

1 つの射影だけを置き換えて、WikiText-2 の NLL を記事ごとに測った（元のモデル：NLL 2.552、PPL 12.83）。

| 差 | M5 が良い | M5 が悪い | 区間が 0 をまたぐ |
|---|---|---|---|
| M5 − M3 | 34 | 0 | 0 |
| M5 − M1 | 30 | 2 | 2 |
| M5 − M2 | 1 | 32 | 1 |

M5 が M2 より悪い 32 セルの差は +0.0008〜+0.023 nat。

![[assets/04_main_experiment/nll_differences.png]]

## 4. 考察

- **言えること**：出力の誤差に合わせて TT を再最適化すると、普通の TT-SVD と行列の最良の近似の差の多くを、層・射影・予算・ドメインをまたいで回復した。重みの誤差のままの ALS ではほとんど回復しないので、回復は「反復したこと」だけでは説明できない。
- **言えないこと**：「主因は目的関数」「TT の表現の限界」とは書かない。M5 は ALS で得られた 1 つの解にすぎず、TT の最良の解がどこにあるかは分からない。
- **TT は行列に近づくが、ほぼ超えない**：同じ予算で M2 を上回ったのは L21_down の WikiText-2 だけで、NLL でもほとんどのセルで M2 が良い。今回の設定で TT を選ぶ利点は、精度では示せていない。
- **k・v**：射影の出力では high でも、attention の出力までは改善が届かないセルがある。k は softmax を通り、v は頭ごとに重みづけして足し合わされるため、射影の出力の誤差がそのまま attention の出力の誤差にならないと考える（推測）。attention の出力そのものを目的にした最適化は試していない。
- **ドメイン**：C4 で $\rho$ が下がるのは、較正が WikiText 系だからと考える（推測）。それでも全セル high だった。

## 5. 実行と検算

- ALS は 112 本（M5 を M3 から 42、M3F 42、M5 を M4r から 12、$\lambda$ の確認 16）。2 本ずつ同時に回し、各本の時間の合計は約 29.6 時間。局所ソルバーが解けなかった本は 0。M4r から始めた本も、M3 から始めた本と較正の $Q_\lambda$ で 0.33% 以内の解に収束した。
- 評価の検算 566 件はすべて合格した。主なもの：
  - 方式の行列を作り直したときの $Q_\lambda$ が保存値と一致
  - 単位ごとの Gram 行列の和が保存値と一致
  - 置き換えた層から後ろだけを計算した NLL が、モデル全体の値と一致
  - 全方式で同じ再標本を使っている
- 評価のコードは Claude が書き、Codex がレビューした。結果を変える誤りは 0 件だった。頑健さの指摘 6 件を直して集計し直し、値が変わらないことを確かめた。
