## 1. 目的

予備実験（1 層・1 射影）で得た「学習後の TT 圧縮が行列の低ランク圧縮に負ける分の大部分は、目的関数を計量つきに変えれば埋まる」という結果が、別の層・射影・モデルでも成り立つかを確かめる。順番の基本は、予備実験の §9 と §12.5 のとおり：同じ層の `down_proj` → 別の位置のブロック・attention の層 → Pythia-410M → 16.7% の予算・複数層の置換。具体的な範囲は §2 で決めた。結論の書き方は §7.5 のとおりに限る（「主因は目的関数」とは書かない）。

### 用語

- **Q_λ**：較正データで測った、正則化つきの重み付き二乗誤差。Q_λ = ‖(W − Ŵ) G_λ^{1/2}‖_F²。W は元の重み、Ŵ は近似、G は較正データの入力の Gram 行列、G_λ = G + λ·tr(G)/n·I（n は入力の次元）。ALS はこれを下げる。
- **M2**：G_λ で白色化した SVD。同じ予算・同じ目的関数での、行列の厳密な最適解。
- **M3**：普通の TT-SVD（Frobenius 誤差）。
- **M4_retruncated（M4r）**：対角の重みをつけた TT を、同じランクに作り直したもの。M5 の初期値の候補。
- **M5**：Q_λ を 1 サイトの ALS で最小化した TT。
- **掃引（sweep）**：ALS で、コアを端から端まで 1 往復して全部を 1 回ずつ更新すること。
- **e**：相対二乗誤差（Q を ‖W G^{1/2}‖_F² で割ったもの）。
- **ρ**：ρ = (e(M3) − e(M5)) / (e(M3) − e(M2))。TT-SVD と最良の行列近似の差のうち、M5 で埋まった割合。
- **s_k、s_max**：掃引の終わりの状態で、更新せずに測り直したサイト k の局所勾配の相対ノルム（そのコアがまだどれだけ改善できるかの指標）。s_max はその全サイトでの最大値。定義は 03 の design.md の §4。

### 2.3 結合の飽和の分類（回す前に固定）

- 結合 b ごとに、ランクと構造上の最大の比 r_b / r_b,max を記録する。
- すべての結合で r_b / r_b,max ≤ 0.9 → `multi_cut`（複数か所を切る TT）
- どれか 1 本でも > 0.9 → `near_saturated_bond`（実質 1 か所だけで切った TT に近い）
- 0.9 は前もって決めた実用上の値で、理論的な根拠はない。
- 該当するのは、Qwen3 では 50% の k・v（63/64）だけ。**Pythia では 50% の dense（63/64）・h_to_4h（126/128）・4h_to_h（126/128）の 4 射影中 3 つ**。そのため Pythia で `multi_cut` になるのは、50% の qkv と 25% の 4 射影の 5 セルだけで、外部確認での「複数か所を切る TT」の結論はほぼ 25% に頼る。
- `near_saturated_bond` の条件も削除しない（行列の低ランク近似に近い TT での対照になる）。結果は「全条件」「`multi_cut` だけ」「`near_saturated_bond` だけ」に分けて集計する。

### 2.4 数え方

- 同じ入力（同じ G_λ）を使う射影（q・k・v、gate・up）も、重み・出力の次元・構造上のランクが違うので別の条件として数える。ただし独立な標本とは数えない。
- 報告は入力のグループごとに並べる：attention の入力（q・k・v）、attention の出力側の入力（o）、MLP の入力（gate・up）、gate を通った MLP の入力（down）。
- 層は 3 つなので、層をまたいだ統計的な検定はしない。「何セル中いくつで ρ ≥ 0.5 か」「e(M5) − e(M2) の区間が 0 を含まないセルはいくつか」といった記述にとどめ、独立な試行の成功率や検定に変えない。
- 言えること：データの計量を使った TT の最適化が、普通の TT-SVD と行列の低ランク近似の差をどの程度埋めるかを、Qwen3-0.6B の内部の 3 つの深さ・全主要射影と、別系統のモデルの代表的な層で調べた。
- 言えないこと：LLM 一般で成り立つ、TT 表現の真の最適解に届いた、どの tensorization でも同じ、推論の計算量でも行列の低ランクより優れる、複数層を圧縮しても同じ性能を保つ。

### 2.5 範囲の例外（前もって決めた規則でだけ認める）

- 認めるもの：g/e(M3) < 0.05（`small_baseline_gap`。§4.1）、必須の検算の失敗、値が有限でない、局所ソルバーの「解けなかった」（§3）、メモリ不足、試運転の実測が時間の上限を超える、checkpoint やモデルの revision の不一致、必要な数の較正文書を確保できない、データの重複・破損、実装上同じ比較の条件を保てない。
- 除外した条件も、理由（`not_run`、`denominator_not_informative`、`solver_failure`、`resource_limit` など）をつけて結果表に残す。
- 時間の上限を超えた場合は、都合の悪い 1 セルだけを外さず、同じ射影の種類・同じ予算・同じ段階に同じ規則を当てはめる。
- 認めないもの：ρ が低かったのでその射影を外す、M5 が M2 に届かなかったので別の tensorization を足す、良い層だけを深さの比較に残す、Pythia の結果が悪かったので別のモデルに差し替える。
- 時間の上限は §6.5。

## 3. ソルバー（確定。2026年11月8日）

- 03 と同じ：GPU、`precision="float32_refine"`（float32 で解いて float64 で直す）、`preconditioner="jacobi"`、`cg_tolerance_mode="fixed"`、`cg_relative_tolerance=1e-8`、`max_cg_iterations=500`、`max_refinements=5`。Q_λ が増える更新は棄却する。
- 局所問題の結果を 3 つに分ける。03 では「1e-8 に届かない」だけで本全体を止めたが、50%・M4r は残差 1.19e-8 で止まっており、基準として脆すぎた。

### 3.1 届かなかったときの解き直し（確定。2026年11月8日）

目標（float64 で測った最終の相対残差 ≤ 1e-8）に届かなかったら、だんだん厳しく解き直す。

| 段 | 解き方 | 次へ進む条件 |
|---|---|---|
| 1 段目 | `max_refinements=5`（ふだんの設定） | 1e-8 に届かない |
| 2 段目 | 1 段目の解の**続きから**、外側の反復の累計 10 回まで（2026年11月8日に変更。下の注） | 1e-8 に届かない |
| 3 段目 | 2 段目の解の**続きから**、外側の反復の累計 50 回まで | — |

- **変更（2026年11月8日、ユーザーが確定）**：最初は 2・3 段目を「最初から」解き直す（03 と同じ）としていた。しかし Claude の確認（§6.2b の 3）で、M4r の状態から回すと真ん中のコアの更新が毎回 3 段目まで進み、1・2 段目の計算（外側の反復 15 回分）を捨てるために 1 掃引がふだんの 11〜15 倍かかった。目標の残差・τ_warn・区分・受理の判定は変えずに、前の段の解の続きから解くことにした（Cursor への依頼 01c）。段の上限は外側の反復の累計（5・10・50 回）で、最初からの場合の合計（最大 65 回）より少ない。

| 区分 | 条件 | 扱い |
|---|---|---|
| 目標に届いた | どれかの段で残差 ≤ 1e-8 | そのまま受理の判定へ。2・3 段目まで進んだ場合は、その回数を記録する |
| 目標に届かなかった（警告） | 3 段目の解の残差 ≤ τ_warn、値が有限、かつ候補の Q_λ が今の値以下 | **3 段目の解**を受理し、警告 `local_target_missed` を記録して続ける |
| 解けなかった | 3 段目でも残差 > τ_warn、値が有限でない、または float64 の CG で曲率が 0 以下になった（float32 の内側の CG での曲率 ≤ 0 は含めない。下の注） | `local_solver_unresolved` で止める。扱いは 03 と同じ（失敗した掃引は捨て、最後に完了した掃引の終わりを最終状態にする） |

- 受理するのは、いつも「得られた中で一番厳しく解いた解」になる。実験の途中で規則が変わることはない。
- 3 段目まで進んだ局所問題では、毎回次を記録する：掃引・サイト、各段の残差・CG の反復数・時間、2 段目と 3 段目の候補の Q_λ、確認の値 a = (Q_λ(2 段目の解) − Q_λ(3 段目の解)) / D_ref（D_ref は §4.1）。a は「2 段目で受理していたら、どれだけずれたか」を示す記録で、規則には使わない。
- 3 段目の解には、残差 1e-12 に届くことを求めない（G の条件数が約 3e14 と大きく、届かない可能性があるため）。

### 3.2 τ_warn の決め方（確定。値は事前の確認で決まる）

- 候補は 1e-7 だけ。ほかの値は探さない。
- 事前の確認：
  1. 03 の 50%・M4r の 426 掃引目の終わりの状態（`models/50_llm_tt_vs_matrix/10_qwen3_0p6b_base/03_long_als_convergence/long_als_T2_50_M4_retruncated.pt`）から回し、03 で止まった局所問題（427 掃引目のサイト 1）で 3 段目の残差を測る。
  2. 試運転（§6.5）で 3 段目まで進んだ局所問題すべて。
- どの例でも 3 段目の残差が 1e-7 以下で、値が有限なら **τ_warn = 1e-7** に固定する。1 つでも届かなければ **τ_warn = 1e-8** とする（警告で続ける区分はなくなり、03 と同じ厳しさになる）。
- 理論の上限（局所の目的関数の誤差 ≤ 残差² ÷ 最小固有値）は、G の条件数が大きく緩すぎて使えないので、実測で決める。

### 3.3 解き直しの費用の歯止め（確定）

- 3 段目は 1 回あたり最大で CG 約 25,000 回で、`up_proj` で十数秒、`down_proj` で 40 秒前後かかる見込み（推定。1 回の HVP の計算量の比から）。03 では、M4r から始めた本の 427 掃引で 2 段目まで進んだのが 8 回、M3 から始めた本では 0 回だった。
- 試運転で、入力のグループ（attention の入力、o の入力、MLP の入力、down の入力）ごとに、2 段目以上に進んだ回数と時間を測る。**2 段目以上に進んだのが局所の更新の 10 回に 1 回を超えるグループがあれば、本実行の前に止めて相談する。** 10% は前もって決める目安で、根拠はない。
- 03 の試運転では、M4r から始めた本で 1 掃引目から届かない更新が出ていたので、試運転には M4r から始める本も入れる（§6.5）。

### 3.4 そのほか

- 実装の注意（コードを読んで分かったこと）：今の `_conjugate_gradient` は、曲率が 0 以下になると何も記録せずにループを抜ける（`src/nn_compression/tt_mps/metric_tt_solver.py` の 461 行付近）。終わり方の状態を結果として返すようにする。
- **曲率の扱いの修正（2026年11月8日、Cursor への依頼文を作るときに Claude が直した）**：最初は「CG で曲率が 0 以下 → 解けなかった」としていた。しかし局所ヘッセ行列は正定値なので、正確な計算なら曲率は必ず正で、float32 の内側の CG で曲率が 0 以下になるのは、G の条件数（約 3e14）と float32 の丸め（相対で約 6e-8）による数値の誤差としてありうる。これは外側の反復（float64 で残差を測り直す）で正される。そこで、float32 の内側の CG での曲率 ≤ 0 は回数を記録するだけにし、解けたかどうかは float64 で測った残差と、値が有限かどうかで決める。float64 の CG での曲率 ≤ 0 は「解けなかった」のまま。
- 03 の判定（50% は `local_solver_unresolved`）は、決めた規則による結果なので、さかのぼって変えない。

## 4. 停止の規則（確定。2026年11月8日）

### 4.1 規則

止める判断は、50 掃引ごとの保存のときにだけ行う。s = 50, 100, 150, … について、

```
D_ref  = max( Q_λ(M3) − Q_λ(M2),  0.05 · Q_λ(M3) )
Δ₅₀(s) = ( Q_λ(s − 50) − Q_λ(s) ) / D_ref
```

を計算する。Q_λ(0) は ALS を始める前の値。Q_λ(M3) と Q_λ(M2) は、同じ較正データ・同じ G_λ・同じ予算で計算する。

| 停止の理由 | 条件 |
|---|---|
| `study_resolution_reached` | **Δ₅₀(s) < 1e-4 と Δ₅₀(s − 50) < 1e-4 が両方成り立つ**（2 回続けて） |
| `max_sweeps` | **1,000 掃引**に達した |
| `local_solver_unresolved` | §3 の「解けなかった」が出た |

- 最終状態は、最後に完了した掃引の終わり（03 と同じ）。
- **s_max は保存のたびに記録するが、止める判断には使わない。** 1 掃引ごとの相対減少も使わない（値がばらつくため）。
- **`small_baseline_gap`**：Q_λ(M3) − Q_λ(M2) < 0.05·Q_λ(M3)（TT-SVD と行列法の差が、M3 の誤差の 5% 未満）の条件には、この印をつける。そのときは D_ref の下限が効くので、Δ₅₀ を「ρ の単位の改善量」とは呼ばない。ρ を主な指標にせず、M2・M3・M5 の誤差の差をそのまま報告する。5% は、予備実験で決めた「g/e(M3) の下限 0.05」と同じ値で、研究の問いの信号が小さすぎる条件を分けるための、前もって決めた実用上の基準である（数学的な根拠はない）。
- 検証データは止める判断に使わない。

### 4.2 根拠

- この規則は「ALS が収束した」ことを判定するものではない。**研究上の判定の精度に対して、追加の計算で得られる改善が十分小さくなったら打ち切る**ための規則である。
- 03 では、どの本も s_max が 1e-4〜1e-3 にとどまった。s_max は掃引数の −0.8〜−0.9 乗でしか減らず、1e-6 には 10⁵ 掃引以上かかる見込みで、停留性の基準は使えなかった。
- D_ref で割ると、Δ₅₀ はおおむね「直近 50 掃引で較正データの ρ が増えた量」になる（下限が効かない場合）。単位が層によらないので、層をまたいで同じ規則を使える。
- 03 の記録に当てはめた結果（`results/50_llm_tt_vs_matrix/10_qwen3_0p6b_base/03_long_als_convergence/history.csv` から Claude が計算し、ChatGPT の値と一致した）：

| 本 | 初めて 1e-4 未満 | 止まる掃引（2 回続けて） | 止まった時点と 1,000 掃引目の差（ρ / Q_λ） |
|---|---|---|---|
| 50%・M3 | 300 | 350 | 3.64e-4 / +0.13% |
| 25%・M3 | 350 | 400 | 4.45e-4 / +0.10% |
| 50%・M4r | なし（426 掃引目で 6.7e-4） | なし | — |
| 25%・M4r | なし（1,000 掃引目で 1.4e-4） | なし | — |

  ρ の差 4e-4 前後は、判定のしきい値 0.2 / 0.5 より 3 桁小さい。
- 2 回続けることにしたのは、1 回だけ偶然小さくなった場合を避けるため。余分にかかるのは 50 掃引（T2・50% で約 2 分）。
- 上限を 1,000 にしたのは、25%・M4r が 400 掃引目でまだ最終の値より約 1.1% 高く、500 では初期値の比較が足りないため。計算の本数が増えたら、別の計算予算の規則を前もって設計する。

### 4.3 限界と、書き方

- 止めた時点は「改善が見えなくなった」だけで、収束したとは言えない。M5 は「指定した最適化の予算の中で得られた最良解」（best attained TT solution）と呼び、「最適な TT」「収束した TT」とは呼ばない。
- **偏りの向き**：早く止めると e(M5) は大きめに出る。
  - ρ は、さらに最適化したときの値より小さめに出る。→「計量つきの目的関数で TT-SVD との差を埋められた」という主張には控えめな側。
  - e(M5) − e(M2) は大きめに出る。→「残りは TT の表現の限界である」という主張には**有利な側**。表現の限界について書くときは、最適化の誤差が混ざった上限であることを必ず書く。
- 論文での書き方の案：「ALS は停留性の基準まで収束したとは限らない。すべての本を、M3 と M2 の誤差の差に対する直近 50 掃引の改善量が所定の値を下回った時点、または最大の掃引数で止めた。」
- 規則を作るのに 03 のデータを使ったので、03 と同じ条件（layer 14 の `up_proj`）は規則の確認に数えない。確認になるのは、規則を変えずに使った別の層・別のモデルの結果だけである。

### 4.4 外挿（報告だけ。止める判断には使わない）

- 1 掃引の相対減少を d(s) ≈ c·s^{−p} で当てはめる。末尾の区間は複数とって p を推定する。
- p > 1 の場合だけ、残りの減少の推定値を、その 2 倍とあわせて参考範囲として示す。
- 測定値を外挿値で補正しない。

### 4.5 記録（保存のたび）

Q_λ、正則化なしの Q、Δ₅₀、s_k と s_max、警告 `local_target_missed` の数、検証データでの e（検証の Gram 行列の合計から計算。診断用）。サブ層の出力の誤差は、最終の状態についてだけ評価の段階で計算する（2026年11月8日、依頼 02 を作るときに Claude が修正。途中で計算するとモデル全体を流す必要があり重いため）。毎掃引の記録は 03 の §7 と同じ。

## 6. GPU と計算の効率（順番は確定。中身は計測してから決める）

### 6.1 今の内訳（03 の T2・50%・M3 の測定事実と、コードを読んで分かったこと）

- 1 掃引は約 2.47 秒（最後の 200 掃引の中央値）。
- 局所ヘッセ×ベクトル（HVP。CG 1 回ごとに 1 回）は 1 掃引に約 2,070 回で、合計約 1.12 秒（1 回あたり約 0.54 ms）。そのうち約 2,000 回は真ん中のコア（サイト 1）の更新で、毎回 CG の上限（500 回 × 外側の反復 2 回）に達している。
- 1 回の HVP は、コアから密な行列 Ŵ（3072×1024）を作り直し、G を掛け（約 6.4 GFLOP）、随伴の縮約をする。TF32 は無効。
- HVP 以外の約 1.35 秒/掃引の原因として有力なのは、CG の 1 回ごとに `.item()` で CPU に値を 2 回取り出して待つこと（曲率と残差。1 掃引で約 4,100 回）と、小さいカーネル。**プロファイルはしていない。**
- GPU の使用率は平均 70% 前後。1 本あたりのメモリは約 270 MB。
- `down_proj`（3072 → 1024）では G が 3072×3072 になり、1 回の HVP の行列積は約 19 GFLOP（`up_proj` の約 3 倍）。CG の回数は分からない（推定、未測定）。

### 6.2 作業の順番

1. **プロファイル**：代表的なサイト 1 の更新について、HVP、前処理、norm・dot、CPU–GPU の同期、カーネルの間の空白、QR・受理の判定の時間を分ける。
2. **CG を GPU の上で 10 回ずつまとめて回す**：収束の確認は 10 回ごとにだけ CPU に返す。曲率の判定と値が有限かどうかの判定は GPU の上のフラグにためて、区切りで確かめる（§3 の区分にも使う）。最大 9 回余分に回るので、反復の回数と丸めの順番が変わる。旧実装と、最終の float64 残差、局所解、5〜50 掃引後の Q_λ、掃引の時間を比べてから採用する。CUDA Graph は、これができてから検討する。
   - **合格の条件（前もって固定）**：layer 14 の up（開発用）と down の 50%・M3 から始めた本を、旧実装と新実装で 50 掃引ずつ回す。(a) すべての局所問題が同じ規則（§3）で扱われている（目標に届くか、届かない場合は同じ区分になる）、(b) 50 掃引後の |Q_λ(新) − Q_λ(旧)| / D_ref ≤ 1e-6（停止のしきい値 1e-4 の 1/100）。受理・棄却の判定、CG の反復の回数、時間は記録する。
3. **1 本で測り直す。**
4. **2 本を同時に回して実測する**（コードを変えずに、2 プロセスで試す）。1 本ずつ回した場合と、2 本の合計の完了時間を比べる。

### 6.2a 結果と決定（2026年11月8日。ユーザーが確定）

- **区切りの CG（`cg_check_every > 1`）は使わない。** 依頼 01・01b で実装したが、どちらも元の CG より遅かった（up_proj・50% の真ん中のコアの局所問題、CG 1,000 回で、CG 1 回あたり `cg_check_every=1` が 0.95〜1.2 ms、`cg_check_every=10` が 1.6〜1.9 ms。Cursor と Claude の計測で一致）。反復ごとの小さい演算が増え、Windows ではカーネルの発行が重いため、CPU が GPU に追いつかなくなったと考えられる（プロファイルでは確かめていない）。コードは残すが、本実験では使わない。
- **本実験の設定は `cg_check_every=1`、`timing_sync=False`**（時間を測る仕組みが GPU を待たない。計算結果は同じことを単体テストで確認）。

- CUDA Graph は入れない。減らせるのは CPU が処理を頼む時間だけで、GPU の計算は減らないので、伸びしろは同じく 1.3 倍前後と見込むため（推定）。
- 大きく速くするには CG の回数そのものを減らすしかない（真ん中のコアは毎回の更新で CG の上限 500 回 × 2 に達している）。これは §6.4 の論点で、時間が 48 時間を超える場合だけ検討する。
- 依頼 01 の F の 2 つ目（`cg_check_every` が 1 と 10 で同じ結果か）は、10 を使わないので行わない。代わりに、新しい関数（`run_metric_tt_als_study`）で down_proj・50%・M3 を 50 掃引回して、実際のデータで動くかと 1 掃引の時間を確かめ、up_proj・50%・M3 の 50 掃引が 03 の記録と一致するかを確かめる。G（τ_warn の事前の確認の 1 つ目）は予定どおり行う。

### 6.4 局所の許容誤差を緩める方法（止め方とは別に検証する）

- 案：τ_k = max(1e-8, 0.1·s_k)。外側が粗いうちは局所問題を粗く解き、停留点に近づくと厳しくする。真ん中のコアの CG が HVP の約 97% を占めるので、GPU の調整より効く可能性がある（未測定）。
- ただし、ALS の軌道、初期値への依存、止まる掃引、最終の M5 と ρ が変わりうる。単なる高速化ではない。
- 順番：(1) 固定の 1e-8 で停止の規則を確定する（済み）→ (2) CG の同期を減らす（数学的には同じ計算の高速化）→ (3) 代表的な条件で、固定の場合と比べる → (4) ρ、最終の誤差、止まる掃引、時間が許容範囲なら採用する（許容範囲は比べる前に決める）。
- 採用する場合は全セルに同じように使う。一部のセルを固定の 1e-8、残りをこの方法で回すことはしない。

## 7. 判定の規則と評価（確定。2026年11月8日。結果を見る前に固定し、結果を見てから変えない）

### 7.1 方式

| 方式 | 内容 | 役割 |
|---|---|---|
| M1 | 普通の SVD（Frobenius 誤差で rank r） | 基準（データを使わない行列） |
| M2 | G_λ で白色化した SVD | 基準（Q_λ のもとでの rank r の行列の厳密な最適解） |
| M3 | 普通の TT-SVD | 基準（Frobenius 誤差の TT） |
| **M3F** | M3 から始めて、**Frobenius 誤差のまま** 1 サイトの ALS を回した TT | 対照（新規。報告だけ） |
| M4 | diagonal-metric TT（入力のチャネルごとの RMS で重みをつけた TT-SVD。予備実験の M4） | 補助（報告だけ） |
| M5 | Q_λ を 1 サイトの ALS で最小化した TT（M3 から始める。§5.1） | 主な方式 |

- **M3F を足す理由**：M3 → M5 では、目的関数（Frobenius → 計量つき）と計算の方法（1 回の分解 → 反復の ALS）が同時に変わる。M3F は計算の方法だけを M5 にそろえ、目的関数は M3 のままにしたもので、2 つを分けて測る。
- M3F の解き方：G = I なので、正準形では局所問題が閉じた式（中心のコア ＝ 左右の環境で W を射影したもの）で解ける。CG は使わない。計算はほぼかからない見込み（推定）。
- M3F の停止の規則：§4 と同じ形で、目的関数を F = ‖W − Ŵ‖_F² にしたもの。D_ref^F = max(F(M3) − F(M1), 0.05·F(M3))（M1 は Frobenius 誤差のもとでの rank r の行列の最適解）、Δ₅₀^F < 1e-4 が 2 回続いたら止める、上限 1,000 掃引。
- M4b（AWT）は実装しない。

### 7.3 区間の作り方

- **対になったクラスタのブートストラップ**：M1〜M5 と M3F のすべてを、同じ単位（記事・文書）の同じ再標本で計算する。
- 各再標本では、単位ごとの「誤差の二乗和」と「元の出力の二乗和」をそれぞれ足し合わせてから e を計算する。単位ごとの比を平均しない。
- 回数は **10,000 回**、seed 0。百分位の 95% 区間。
- 各再標本で次を計算する：
  - D = e(M3) − e(M2)（TT-SVD と最良の行列近似の差）
  - N = e(M3) − e(M5)（M5 で埋まった差）
  - H_c = N − c·D（c = 0.2、0.5）。D > 0 なら「ρ ≥ c」と「H_c ≥ 0」は同じ。
- 分類には ρ の比の区間を使わず、H_c の区間を使う。比の百分位区間は、分母が 0 に近いときにも有限の区間を返してしまい、不安定さを隠すため（Fieller 型の問題。ChatGPT が挙げた文献で、Claude は原典を確かめていない）。
- ρ の点推定と百分位区間は図のためだけに出す。区間は D の区間の下限が正のときだけ出し、百分位法の限界を書く。
- 32〜59 単位のブートストラップの区間は、精度が保証されたものではなく、記述のためのものとして扱う。

### 7.4 セルごとの分類（検証のドメインごとに）

| 分類 | 条件 |
|---|---|
| `denominator_not_informative` | D の点推定 ≤ 0、D の区間が 0 をまたぐ、または D/e(M3) < 0.05（先に当てはめる） |
| `high` | H_0.5 の区間の下限 ≥ 0（ρ ≥ 0.5 が支持される） |
| `mid` | H_0.2 の区間の下限 ≥ 0、かつ H_0.5 の区間の上限 < 0 |
| `low` | H_0.2 の区間の上限 < 0（ρ < 0.2 が支持される） |
| `unresolved` | 上のどれでもない（区間が 0.2 か 0.5 をまたぐ） |
| `not_classified` | M5 の停止の理由が `local_solver_unresolved`。最後に完了した状態の値は参考として残す |

- 0.2 と 0.5 は予備実験と同じ、前もって決めた工学的な目安で、理論的な根拠はない。
- セルにつける印：
  - `optimization_censored`：M5 が `max_sweeps` で止まった。分類はするが、印をつける。
  - `attained_residual_positive`：R_M5 = e(M5) − e(M2) の区間の下限 > 0。
  - `strong_calibration_validation_reversal`：較正では ρ ≥ 0.5 なのに、検証では `low`。「過適合」と断定しない。
  - `lambda_sensitive`：§7.7 の確認で分類が変わった。
  - `near_saturated_bond`・`small_baseline_gap`：§2.3・§4.1 のとおり。
- 毎セル報告する量：e（全方式）、ρ、D、N、R_M5、R_M5/e(M3)、1 − ρ（分母が情報を持つ場合）、κ = (e(M3) − e(M5))/e(M3)。ρ < 0、ρ > 1 も丸めない。
- **R_M5 の読み方**：
  - 較正データの Q_λ では、M5 は得られた TT の解にすぎないので、Q_λ(M5) − Q_λ(M2) は「TT の最良の値と行列の最良の値の差」の上限であり、最適化の誤差を含む。TT の最良の解が M2 より良い可能性もあるので、正の「表現の限界」があるとまでは言えない。
  - 検証データでは M2 は最適解ではないので、R_M5 は「観測された方式どうしの差」にすぎない。
  - どちらの場合も「TT の表現の限界」とは呼ばない。区間が 0 を含まないことと、実用上大きいことも分けて書く。
- **ρ > 1 の場合**：まず M2（白色化の解、予算、評価の計量）を検算し直す。合格したら「同じ保存の予算で、得られた TT の解が、その評価では rank r の行列の解より良かった」と書く。M2 は rank r の行列の中での最適解であり、同じパラメータ数のあらゆる表現の中での最適解ではない。

### 7.5 全体の結論の書き方（前もって固定した記述の規則）

**Qwen3 の主な集計の対象**：確認用の 40 セルのうち `multi_cut` の **34 セル**。分母は 34 に固定し、`unresolved`・`denominator_not_informative`・`not_classified` も分母から除かない。内訳を 34 に対してそのまま示す。

| 書いてよい結論 | 条件 |
|---|---|
| W：「事前に固定した Qwen3 の multi-cut の条件の広い範囲で、計量に合わせた TT の再最適化は、普通の TT-SVD と計量に合わせた行列の低ランク近似の差の半分以上を回復した（WikiText-2）」 | WikiText-2 で `high` のセルが **26 以上**、かつ WikiText-2 で `low` のセルが **0** |
| B：W に「ドメインが変わっても（C4）同じだった」を足す | 同じセルが WikiText-2 と C4 の**両方で `high`** のものが 26 以上、かつどちらかのドメインで `low` のセルが 0 |
| F：「Frobenius の TT-SVD と評価の計量の不一致は、観測された差の大きな、回復できる成分だった。反復の計算だけ（Frobenius のままの ALS）では、差の 2 割も回復しなかった」 | W を満たし、かつ WikiText-2 で M3F について H_0.2^F = (e(M3) − e(M3F)) − 0.2·D の区間の上限 < 0 のセルが 26 以上 |

- 26 は 34 の 3/4 を切り上げた数で、前もって決めた目安。統計的な成功率ではなく、セルどうしは独立でもない（同じ層・同じ Gram 行列を共有する）。検定や成功率には変えない。
- 条件を満たさないとき：
  - `low` があれば「条件によって異なる」と書き、どの入力のグループ・予算で違ったかを示す。
  - `unresolved` が多いときは「効果がない」でも「条件によって異なる」でもなく、「今の検証データの量では判定できない」と書く。
- **書かないこと**：「主因は目的関数」「TT の表現の限界」と断定すること、LLM 一般で成り立つということ。
- `near_saturated_bond` の 6 セルと、開発用の 2 セル（layer 14 の up_proj）は、別の表に並べるだけにする。

**Pythia**：合否を決めず、5 つの `multi_cut` セルと 3 つの `near_saturated_bond` セルの分類の内訳を、射影・予算ごとにそのまま報告する。「第 2 のモデルでも同じ傾向だった」と書いてよいのは、分母が情報を持つ `multi_cut` のセルすべてで ρ の点推定が 0.5 以上で、そのうち過半が `high` で、`low` が 1 つもないときだけ。

### 7.6 報告だけの指標（判定には使わない）

- **サブ層の出力の誤差**（予備実験の E_gated を一般にしたもの）：1 つの射影だけを置き換え、残差を足す前のサブ層の出力で、元のモデルとの相対二乗誤差を測る。

  - §7.2 と同じ検証の単位を使い、同じ規則（分母の判定と H_c の区間）で ρ_sublayer と分類を出す。
  - その層への入力（hidden state）、attention mask は元のモデルと同じにそろえ、cache は使わない。
  - M2 はこの誤差に対する最適解ではない。ρ_sublayer は「行列の最適解との差の回復率」ではない。q・k は softmax を通るので非線形だが、下流での実際の効き方を見る診断として使う。
  - 予備実験と比べるため、up の E_gated も残す。
  - e と ρ_sublayer で結論が違う場合は、レビューで指摘する。
- **NLL**（1 層を置き換えたときの、トークンあたりの負の対数尤度）：
  - WikiText-2 validation を**記事ごとに分けて**評価する（窓が記事をまたがないようにする）。系列の長さと stride は予備実験と同じ決め方を記事ごとに当てはめる。予備実験は全文をつないで評価していたので、値（元のモデルの 12.68 など）とは比べられない。元のモデルも測り直す。
  - 区間は記事を単位とする対になったブートストラップで出す。各再標本で NLL = Σ(記事の NLL の合計)/Σ(記事のトークン数) を計算する。
  - 区間をつけるのは NLL の差：各方式 − 元のモデル、M5 − M3、M5 − M2、M5 − M1。PPL は表示用の値にする。
  - 対象の方式：M1、M2、M3、M4、M5（M3F は入れない）。
  - 解釈の制限：M5 が e では M3 より良いのに、NLL ではいつも悪い場合は、「層の出力の近似は改善したが、モデルの出力への利得は確認できなかった」と書く。
- **そのほか**：M1、M4、κ。
