## 1. この計画の位置づけ

この計画は、NN圧縮を次の順序で発展させるための学習・実装・評価計画である。

```text
CIFAR-10 CNN baseline
→ 行列SVDによるLinear / Conv圧縮
→ Tucker分解
→ Tensor Train（TT）/ MPS
→ DMRG
→ DMRG-likeなNN局所最適化
→ 手法横断比較・再現性確認・技術レポート
```

資格はすべて計画に含めるが、同じ優先度では扱わない。

```text
統計検定2級・統計検定準1級・E資格
    > Pythonデータ分析実践
    > AI実装検定S級
```

研究実装を止めないことを最優先とし、任意資格は後述の実施条件を満たす場合に受験する。

## 4. 期間別の個別計画

### 2026/8〜9: CIFAR-10 CNN + SVD baseline

#### 研究実装

1. 既存のCIFAR-10 CNN baselineを共通コードから再実行する。
2. 学習・検証・テストデータの役割とseed固定方法を確認する。
3. Linear層とConv層を対象に、層別rank探索と複数層の組合せ探索を整理する。
4. rank選択はvalidation dataで行い、test dataは最終評価だけに使用する。
5. 圧縮前、SVD直後、SVD + fine-tuningを分けて記録する。
6. パラメータ数、圧縮率、MACs、accuracy、lossを共通形式で保存する。
7. latencyは測定環境、warm-up、反復回数、batch sizeを固定して参考値として記録する。

#### 統計検定2級

- 記述統計、確率、確率分布、標本分布を復習する。
- 推定、仮説検定、相関、単回帰・重回帰を問題演習で固める。
- 研究結果の平均、分散、信頼区間、群間比較と結び付けて理解する。
- 9月末までに過去問・模擬問題で合格圏を確認する。

#### 完了条件

- CIFAR-10 baselineとSVD圧縮後モデルを同一条件で再実行できる。
- rankの選択理由を、validation指標、圧縮率、特異値情報から説明できる。
- 主要結果をCSVとmatplotlib / seabornの図で再生成できる。
- 統計検定2級の受験日を2026年10〜11月内に設定できる状態にする。

### 2026/10〜11: CIFAR-10 + Tucker

#### 研究実装

1. Conv重み `(out_channels, in_channels, kernel_h, kernel_w)` の各modeを確認する。
2. Tucker-2を基本候補として、入力channel rankと出力channel rankを制御する。
3. 分解した層を、1×1 Conv、core Conv、1×1 Convとして再構成する。
4. Tucker直後とTucker + fine-tuningを分けて評価する。
5. SVDとTuckerを、同程度のパラメータ数またはMACsで比較する。
6. rank探索範囲、選択規則、fine-tuning条件を保存する。

数値例として、Conv重みが `(64, 32, 3, 3)` の場合、Tucker-2では出力rank `r_out` と入力rank `r_in` を選び、概算パラメータ数を次で比較する。

```text
元のConv:
64 × 32 × 3 × 3 = 18,432

Tucker-2（例: r_out=16, r_in=12）:
32 × 12 + 16 × 12 × 3 × 3 + 64 × 16
= 3,136
```

#### 統計検定2級

- 弱点分野を過去問ベースで補強する。
- 2026年10〜11月に受験する。
- 不合格の場合は弱点を記録し、研究を止めない範囲で1回だけ再受験枠を設ける。

#### 完了条件

- Tucker分解層について、shape、パラメータ数、MACsを説明できる。
- SVD vs Tuckerを同一データ分割・同一評価指標で比較できる。
- 統計検定2級を受験し、結果と弱点を記録する。

### 2026/12〜2027/2: TT / MPS基礎とPythonデータ分析実践

#### 研究実装

1. 高階テンソル、tensorization、mode、coreの表記を統一する。
2. TT-SVDを小さなNumPy / PyTorchテンソルで実装する。
3. TT-rankとMPSのbond dimensionの対応を理解する。
4. full tensorとTT表現のパラメータ数、再構成誤差を比較する。
5. left / right unfoldingと逐次SVDのshapeをテストする。
6. 最小のTT-LinearまたはMPS層を実装し、forwardの一致を確認する。
7. まず小規模モデルで動作確認し、その後CIFAR-10モデルへの適用可能性を調べる。

数値例として、`16 × 16` 行列を `(4, 4) × (4, 4)` にtensorizeし、TT-rankを `(1, 2, 1)` とした場合、元の256パラメータに対して、coreのパラメータ数は次のように見積もる。

```text
1 × 4 × 4 × 2 + 2 × 4 × 4 × 1 = 64
```

## 5. 手法別の学習・実装順

### SVD

```text
CIFAR-10 baseline再現
→ 層別rank探索
→ Linear / Conv圧縮
→ 複数層のrank組合せ
→ fine-tuning
→ Tucker以降のbaselineとして固定
```

確認する数式は、行列 `W ∈ R^(m×n)` のrank `r` 近似である。

```text
W ≈ U_r Σ_r V_r^T

元の重みパラメータ数: mn
分解後: r(m + n)
```

例として `Linear(784, 512)` をrank 64へ分解すると、biasを除く重み数は次のようになる。

```text
元: 784 × 512 = 401,408
分解後: 64 × 784 + 512 × 64 = 82,944
```

### Tucker

```text
Conv重みのmode確認
→ Tucker-2分解
→ 3つのConvへ置換
→ rank探索
→ fine-tuning
→ SVDと同予算比較
```

### TT / MPS

```text
tensorization
→ unfolding
→ TT-SVD
→ canonical form
→ TT-Linear / MPS層
→ bond dimension探索
→ CIFAR-10へ接続
```

### DMRG / DMRG-like

```text
MPSのnorm・期待値
→ environment
→ 1-site DMRG
→ 2-site DMRG
→ sweep・SVD切り捨て
→ TT / MPS-NNの局所更新
→ 通常fine-tuningと比較
```

DMRGはMPSを使った変分最適化手法であり、単純なSVD圧縮の別名ではない。NNへ局所更新の考え方を移す場合は、問題設定に応じてDMRG-likeと表記する。


### 比較の原則

- baseline、圧縮直後、圧縮 + fine-tuningを分ける。
- rankやhyperparameterはvalidation dataで選ぶ。
- test dataによる繰り返し選択をしない。
- 複雑な手法は、同じパラメータ数または同じaccuracyで単純SVDと比較する。
- 理論MACsと実測latencyを混同しない。
- 単一seedの最高値だけで結論を出さない。
- 実行環境、ライブラリversion、seed、configを記録する。

---

## 8. 進捗確認と計画変更ルール

各期間の最終週に次を確認する。

- 完了条件を満たしたか
- 再実行可能な成果物が残っているか
- 次の手法へ進むためのtestがあるか
- 資格学習が研究実装を圧迫していないか
- 次期間へ持ち越す項目と、その理由が明記されているか

遅延した場合は、次の順で調整する。

1. 追加実験の範囲を縮小する。
2. AI実装検定S級を延期または見送る。
3. Pythonデータ分析実践を延期または見送る。
4. 統計検定2級・準1級・E資格は受験時期を調整する。
5. SVD → Tucker → TT-MPS → DMRG-likeという研究の順序は崩さない。

## 9. 最終到達目標

2028年8月までに、次を満たす。

- CIFAR-10を中心にSVD、Tucker、TT / MPS、DMRG-likeを同一条件で比較できる。
- accuracy、圧縮率、パラメータ数、MACs、latency、training costを報告できる。
- 複数seedと再現性確認に基づいて結論を述べられる。
- DMRGとDMRG-like NN最適化の共通点・相違点を説明できる。
- GitHubのREADMEと技術レポートから代表実験を再現できる。
- 資格学習の成果を研究の統計評価、データ処理、深層学習理解へ接続できる。

最終的な本筋は、資格取得数ではなく、次の研究成果を再現可能な形で完成させることである。

```text
SVD baseline
→ Tucker
→ TT / MPS
→ DMRG-like最適化
→ 公平な比較
→ 再現可能な公開成果
```
