# テスト設計

## 1. 目的

Core API v1はMarkdownだけで固定せず、`tests/` を実行可能なcontractとして使う。

テストでは、

```text
数学的正しさ
shape contract
Public APIの境界値
model非破壊性
autograd/state semantics
既存Notebook互換
```

を分けて確認する。

---

## 2. テスト分類

### 数学・再構成テスト

対象：

```text
SVD
unfold / fold / mode_dot
HOSVD
HOOI
Tucker-2
relative Frobenius error
```

確認例：

- full-rank再構成
- fold/unfold round-trip
- HOOI error history
- TensorLyとの照合
- Tucker-2 effective weight

### API contractテスト

対象：

```text
rank
mode
shape
dtype/device
empty loader
warmup/repeats
training state
```

invalid inputが偶発的なPyTorch内部例外ではなく、意図したTypeError/ValueErrorになることを確認する。

### model変換テスト

確認するもの：

```text
元modelが変更されない
Parameterを共有しない
device/dtype維持
requires_grad維持
bias位置
Conv spatial settings維持
```

### 実験支援回帰テスト

既存Fashion-MNIST/CIFAR-10 Notebookが利用するhelperについて、layer名・return structure・互換keyword等を確認する。

## 4. rank validation

rank関連では最低限、

```text
0
negative
max rank超過
bool
float
Tensor scalar
```

を確認する。

SVD/HOSVD/HOOI/Tucker-2/MACsで「実際には作れないrankをもっともらしく受理しない」ことが目的。

---

## 5. Tensor contract

`unfold/fold/mode_dot` では、

```text
0D/1D Tensor拒否
zero-size dimension拒否
invalid mode拒否
fold target shape不整合拒否
mode_dot matrix shape不整合拒否
round-trip維持
```

を確認する。

---

## 6. HOSVD/HOOI

### HOSVD

確認するもの：

```text
partial/full decomposition
empty ranks identity
mode-unfolding rank上限
実数浮動小数点dtype
元Xから独立にfactorを求める挙動
```

### HOOI

確認するもの：

```text
HOSVD初期化
history[0]
max_iter=0
factor key/shape/dtype/device
projected unfolding feasibility
input factors非破壊
convergence tolerance
zero Tensor拒否
```

HOOIの中心数式へ変更を入れた場合は、TensorLy照合を含む数値テストを必ず確認する。

---

## 7. Tucker-2 Conv

確認するもの：

```text
3-layer構造
channel接続
1x1 projection
core spatial settings
bias位置
groups=1
component shape/device/dtype
leaf Parameter
元weightとのstorage非共有
Tensor-level autograd保持
```

HOSVD/HOOIでModule builderを共有しているため、分解と構築のテストを分ける。

---

## 8. training state

評価系APIはmixed training stateを使って確認する。

例：

```text
root = train
BatchNorm = eval
```

呼出前後で全`model.modules()`の`.training`が完全一致することを確認する。

対象：

```text
evaluate
agreement
benchmark_inference
collect_compression_metrics
```

例外発生時の復元もテストする。

---

## 9. DataLoader

### empty

```text
train_one_epoch
evaluate
agreement
logits_rmse
take_inference_batch
```

はemptyを明示的に拒否する。

### no-len IterableDataset

1回走査で完結するAPIでは `len(loader)` を必須にしない。

### one-shot iterator

`collect_compression_metrics()` は複数回走査するため未対応。この制約はテストで「対応している」と誤認しない。

---

## 10. benchmark

最低限、

```text
warmup=0
repeats=1
```

の境界を許可する。

拒否：

```text
warmup < 0
repeats <= 0
bool
float
Tensor scalar
```

baseline/compressedのsame input conditionはNotebook/上位APIでも維持する。

---

## 11. compatibility

旧API名やlegacy keywordは、Core API v1中はcontract testで保持する。

```text
SVD
RebuildSVD
factorize_Conv2d_layer
sweep_conv_svd_ranks
r1/r2
```

互換テストが不要になった場合は、API v2等で削除方針を明示してから外す。

---

## 12. 変更時のテスト追加ルール

Public APIへ変更・追加を行う場合は、最低限次を行う。

```text
1. 正常系
2. 最小/最大境界
3. invalid type/value
4. 元model/stateへの副作用
5. return shape/structure
```

数学アルゴリズム変更なら、さらに、

```text
full-rank/known result
reference implementation比較
```

を追加する。

---

## 13. Core API freeze条件

Core API v1を最終確定する条件：

```text
Public API一覧と__all__が一致
設計書とsignatureが一致
contract testと記述が一致
全pytest green
git diff --check clean
```

設計書だけ更新してテストが追従していない状態ではfreeze完了としない。
