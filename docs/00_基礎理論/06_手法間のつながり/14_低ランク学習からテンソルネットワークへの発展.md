# 低ランク学習からテンソルネットワークへの発展

## サマリー

現在の学習ロードマップは、

```text
SVD
↓
Tucker decomposition
↓
Tensor Train / MPS
↓
DMRG
```

とする。

SVD編では、MNIST → Fashion-MNIST → CIFAR-10を通して、

- Linear weightの低rank化
- Conv weightの行列化SVD
- rank選択
- Fine-tuning
- 複数層のrank allocation
- parameter / MACs / latencyの評価
- 再現性と公平な実験設計

まで確認した。

次は、Conv weightを単なる行列へ潰すSVDから一歩進み、**Tensorの各modeを区別して扱うTucker**へ進む。

---

# 1. SVDで学んだこと

SVDでは、行列、

$$
W\in\mathbb{R}^{m\times n}
$$

を、

$$
W\approx U_r\Sigma_rV_r^{\mathsf T}
$$

へ低rank化する。

NN圧縮では、

```text
大きな1層
↓
小さな2因子
```

として保持することでparameter数やMACsを減らす。

Fashion-MNIST / CIFAR-10では、SVD直後のtask性能が落ちても、Fine-tuningで低rank制約内の性能を回復できることを確認した。

ただしSVDが直接最適化するのはweight近似であり、classification lossではない。

```text
weight approximation
≠
task optimization
```

という区別は、今後のTensor decompositionでも重要。

---

# 2. Conv SVDの限界 — Tensorを行列化している

Conv2d weightは本来、

$$
W
\in
\mathbb{R}^{
C_{out}\times C_{in}\times K_h\times K_w
}
$$

という4階Tensor。

今回のConv SVDでは、

$$
W_{mat}
\in
\mathbb{R}^{
C_{out}\times(C_{in}K_hK_w)
}
$$

へreshapeしてからSVDした。

つまり、

```text
output channel
```

と、

```text
input channel × spatial kernel
```

の2方向だけを見る。

この方法は実装が単純で、Linear SVDとの接続も分かりやすい。

一方で、

```text
C_out
C_in
K_h
K_w
```

という元のmode構造を明示的には使わない。

ここがTuckerへ進む理由。

---

# 3. Tucker decomposition

Tucker decompositionでは、Tensorの各modeに別々のrankを持たせる。

このリポジトリではPyTorchのaxis番号に合わせて、Conv weight

$$
W\in\mathbb R^{C_{out}\times C_{in}\times K_h\times K_w}
$$

のmodeを0始まりで数える。

```text
mode 0 = C_out
mode 1 = C_in
mode 2 = K_h
mode 3 = K_w
```

したがってchannel modeだけを圧縮するTucker-2は、

$$
\boxed{
W
\approx
G
\times_0 U_{out}
\times_1 U_{in}
}
$$

と書く。

ここで、

$$
U_{out}\in\mathbb R^{C_{out}\times R_{out}},
\qquad
U_{in}\in\mathbb R^{C_{in}\times R_{in}},
$$

$$
G\in\mathbb R^{R_{out}\times R_{in}\times K_h\times K_w}
$$

である。

Conv圧縮では典型的に、

```text
1×1 Conv
→ 3×3 core Conv
→ 1×1 Conv
```

の形へ対応させられる。

SVDとの違いは、

```text
SVD
→ matrix rank r

Tucker
→ modeごとのmultilinear rank
```

を持つこと。

## Tuckerで学ぶべき最小項目

- Tensorのmode
- unfolding / matricization
- Tucker rank
- core tensor
- mode-n product
- Conv weightへの適用
- parameter数 / MACsの計算
- SVDとの比較

DMRGへ進むことが最終目的なので、Tucker理論を過度に深掘りするより、**「Tensorをmodeごとに圧縮する」という発想を身につける**ことを優先する。

---

# 4. Tensor Train / MPS

Tensor Train（TT）は、高階Tensorをchain状の小Tensorへ分解する。

物理分野のMatrix Product State（MPS）と数学的に非常に近い構造を持つ。

```text
Tensor Train
≈
MPS
```

と考えると、NN圧縮からDMRGへの橋渡しになる。

TT / MPSでは、隣接coreをつなぐ内部次元、

```text
TT rank
bond dimension
```

が表現力と圧縮率を決める。

SVDのrankと似た役割を持つが、同一概念ではない。

```text
SVD rank
→ 2分割したmatrixのrank

bond dimension
→ chain型Tensor network内部の接続次元
```

として区別する。

---

# 5. DMRG

DMRGは、MPSのbond dimensionを固定しながら、局所Tensorを順番に最適化していく変分法として理解すると、今回のNN圧縮と接続しやすい。

概念的には、

```text
SVD
→ 低rank構造を作る

Fine-tuning
→ 低rank構造を保ったまま全parameterを勾配法で再最適化

DMRG
→ MPS / TT構造を保ったまま局所Tensorをsweepして最適化
```

という違いになる。

DMRGをNNへ適用する段階では、

- 何をMPS / MPOとして表すか
- objectiveを何にするか
- local optimizationをどう実装するか
- gradient-based trainingとどう比較するか

を考える必要がある。

SVD実験からDMRG性能を直接主張することはできない。

SVD編は、**低自由度表現を作り、その制約内でtask性能を回復する**という前提を実験で理解する段階。

---

# 6. CIFAR-10のrank allocationが次へつながる理由

Fashion-MNISTでは、主にsingle-layer rank selectionを扱った。

CIFAR-10では、

```text
conv1
conv2
conv3
```

へ異なるrankを配るmodel-wide rank allocationへ進んだ。

最終rankは、

```text
conv1=9
conv2=32
conv3=48
```

だった。

ただし、これは各層single-layer knee近傍へ探索空間を制約した結果で、全rank空間のglobal optimumではない。

この経験は、Tucker / TTでも、

```text
どこへどれだけrank / bond dimensionを割り当てるか
```

という問題へそのままつながる。

---

# 7. SVD編から持ち越す実験原則

Tensor decomposition手法が変わっても、次はそのまま使う。

1. Testをrank選択に使わない。
2. Candidate比較では乱数条件を揃える。
3. DataLoader Generatorを評価処理で進めない。
4. Baselineとcompressed modelを共有しない。
5. parameter数・MACs・latencyを別々に測る。
6. 理論演算量削減をwall-clock speedupと同一視しない。
7. Fine-tuning前後を分けて記録する。
8. single seedの小差を性能改善と断定しない。
9. rank選択規則とdecomposition実装を分離する。
10. historical runを残し、formal resultはcorrectedへ一本化する。

これらはSVD固有ではなく、Tucker / TT / DMRG比較でも必要な実験基盤。

---

# 8. 今後の順番

```text
1. Tucker
   Conv weightを多モードのまま圧縮
   SVDとのparameter / MACs / accuracy比較

2. Tensor Train / MPS
   chain型Tensor decomposition
   TT rank / bond dimensionを理解

3. DMRG
   MPS / TT表現を局所sweepで最適化
   gradient-based trainingとの比較
```

SVDをもう一度別データセットで繰り返すより、次は**Tensor構造を保つdecompositionへ進む**。
