## 2. Pythia に固有の点

### 2.1 モデル

- `EleutherAI/pythia-410m` の標準の版（deduped ではない）の最終チェックポイント（`main`）。
- 選ぶ理由：Pythia の系列の標準のチェックポイントで外部確認をするため。deduped 版を選んでも評価データとの重複の懸念はなくならないので、両方は回さない。
- 実行のときに記録するもの：repository ID、解決した commit SHA、チェックポイントの名前と step、tokenizer の revision、model config、重みの dtype。
- 24 層・hidden 1024 などの構成は、ダウンロードしてから config で確かめる（今は Claude の知識と ChatGPT が挙げた公式の config による。Claude は未確認）。
- ダウンロード（約 0.8 GB）は、この段階に入るときにユーザーの許可を得る。キャッシュは Qwen3 と同じ `data/hf_cache/`。

### 2.2 層と射影

- 層：**0 から数えて 12（13 番目のブロック）**。24 層の真ん中は 11 層と 12 層の間なので、「真ん中に隣り合う 2 層のうち、前もって選んだ一方」とする（Qwen3 の 14/28 と同じ規則）。
- 射影：qkv（1024→3072）、attention の dense（1024→1024）、h_to_4h（1024→4096）、4h_to_h（4096→1024）の 4 つ × 予算 50%・25% ＝ 8 セル。
- qkv は 3 つの射影をまとめた 1 つの行列のまま圧縮する。
- 形とランク、結合の飽和の分類は正本の §2.2・§2.3 の表のとおり。50% の dense・h_to_4h・4h_to_h は `near_saturated_bond` で、`multi_cut` は 50% の qkv と 25% の 4 射影の 5 セルだけ。
- 入力のグループ：attention の入力（qkv）、attention の出力側の入力（dense）、MLP の入力（h_to_4h）、MLP の中間の入力（4h_to_h）。Pythia は attention と MLP を並列に計算し、それぞれ別の LayerNorm を通すので、qkv と h_to_4h の入力の Gram 行列は別になる（実装で確かめる）。

### 2.3 バイアス

- Pythia の線形層にはバイアスがある。バイアスは圧縮せず、元の値を全方式で保持し、予算の外に置く。
- 誤差 e は (W − Ŵ)x で測るので、バイアスは打ち消し合い、目的関数にも判定にも入らない。
- パラメータ数は「圧縮する重みだけ」と「バイアスを含む射影全体」の 2 通りを報告する。
- サブ層の出力と NLL の評価でも、バイアスは元の値を使う。

### 2.4 データ

- 較正・検証の作り方は正本の §7.2 と同じ規則を、Pythia のトークナイザーで当てはめる（較正は WikiText-103 train の 128 系列 × 1,024 トークン、WikiText-2 validation の 1,024 トークン以上の記事を全文、C4 validation の 1,024 トークン以上の文書から 128 文書）。
- トークナイザーが違うので、「1,024 トークン以上」の記事・文書の数や、選ばれる文書が Qwen3 と変わりうる。規則は変えずに、数と文書の hash を記録する。
- 学習データとの重複：照合しない。書き方は正本の §2.1 のとおり（「較正に使っていない固定の文書で評価した。事前学習のデータとの文書の重複は照合していない」）。

### 2.6 報告だけの追加指標（先頭のトークンと固有方向）

2026-11-09 に追加。Qwen3 の追加分析（`results/50_llm_tt_vs_matrix/10_qwen3_0p6b_base/04_main_experiment/followup_analysis/`、考察は `docs/60_LLM_TT_vs_Matrix/10_Qwen3_0p6B_Base/05_考察_TTは行列にどこまで迫れたか.md` §7）で次の 2 つが分かったので、Pythia では最初から同じ量を測る。

- C4 で $\rho$ が下がる分は、較正 Gram 行列の固有方向で、較正データにほとんど乗らない向き（257 位以降）から来ていた。
- k・v のサブ層での弱さは、区間の先頭のトークン（attention sink：注目の 41〜69% が集まる）に集中していた。k は M2 でも壊れ、v は M5 だけが先頭の値を外した。

**判定の規則（正本の §7.4・§7.5）は変えない。** ここに書く量はすべて報告だけの指標で、分類や結論の判定には使わない。

測るもの：

1. **先頭のトークンへの注目の割合**：層 12 の全 head・全 query の平均。WikiText-2 と C4 で別々に。Pythia に attention sink があるかの確認になるので、最初に測る。
2. **qkv のセル（50%・25%）**：置き換えた重みを使う位置を「全部の位置」「先頭のトークンだけ」「先頭以外だけ」の 3 通りに分け、M2・M3・M5 の誤差を、softmax 後の重み、head ごとの出力、dense の後（サブ層の出力）の 3 段階で測る。
   - qkv は 1 つの行列なので、置き換えは q・k・v を同時に行う。それに加えて、近似の誤差 $W-\hat W$ の行を q・k・v の部分に分け、「k の部分だけを近似に替え、q・v は元のまま」のように 1 つずつ置き換えた版も測る（Qwen3 の k・v と比べるため）。
3. **dense のセル**：置き換えを「先頭のトークンだけ」「先頭以外だけ」に分けた、サブ層の出力の誤差。
4. **固有方向の帯ごとの分析**：評価のあとに、保存済みの重み・Gram 行列・方式の結果から計算する（モデルを動かさない）。帯は Qwen3 と同じ 1〜16、17〜64、65〜256、257 位以降。出す量は、帯ごとの M3−M2 と M5−M2（較正・WikiText-2・C4 の重みで）、検証と較正の重みの比、帯ごとの M5 ÷ M2。
5. ALS の最終の $s_{\max}$・掃引数・時間・ピークメモリは、正本の仕組みで履歴（`history.csv`）に記録されるので、追加の作業はない。

実装の注意：

- スクリプトは Qwen3 の `notebooks/50_llm_tt_vs_matrix/10_qwen3_0p6b_base/04_followup_attention_stages.py`・`04_followup_sink_test.py`・`04_followup_eigen_directions.py`・`04_followup_band_ratio.py` を元にする。
- Pythia（GPT-NeoX）は attention と MLP を並列に計算し、位置の回転（RoPE）を head の次元の一部にだけ掛ける。q・k に正規化（Qwen3 の q_norm・k_norm）はない。qkv の出力の並び方（head ごとに q・k・v が並ぶか）も Qwen3 と違う。なので、attention を段階ごとに自分で計算する部分は書き直しが要る。並び方は実装で config とコードから確かめる。
- 検算は Qwen3 と同じ：元の重みで、自作の計算が元のモジュールの出力と float32 の誤差の範囲で一致すること。サブ層の出力の誤差が、正本の §7 の評価（`cells_sublayer.csv` に当たる値）と一致すること。
- 区間の先頭には特別な開始記号を足さない（Qwen3 と同じ）。先頭のトークンは、区間の 1 番目の普通のトークン。
