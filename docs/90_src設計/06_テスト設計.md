# テスト設計

## 1. 目的

Core API v1はMarkdownだけで固定せず、`tests/` を実行可能なcontractとして使う。

テストでは、

```text
数学的正しさ
shape contract
Public APIの境界値
model非破壊性
autograd/state semantics
既存Notebook互換
```

を分けて確認する。

---

## 2. テスト分類

### 数学・再構成テスト

対象：

```text
SVD
unfold / fold / mode_dot
HOSVD
HOOI
Tucker-2
TT-SVD / reconstruction
TT canonicalization / rounding
TT inner product / Frobenius norm
relative Frobenius error
```

確認例：

- full-rank再構成
- fold/unfold round-trip
- HOOI error history
- TensorLyとの照合
- Tucker-2 effective weight

### API contractテスト

対象：

```text
rank
mode
shape
dtype/device
empty loader
warmup/repeats
training state
```

invalid inputが偶発的なPyTorch内部例外ではなく、意図したTypeError/ValueErrorになることを確認する。

### model変換テスト

確認するもの：

```text
元modelが変更されない
Parameterを共有しない
device/dtype維持
requires_grad維持
bias位置
Conv spatial settings維持
```

### 実験支援回帰テスト

既存Fashion-MNIST/CIFAR-10 Notebookが利用するhelperについて、layer名・return structure・互換keyword等を確認する。

## 4. rank validation

rank関連では最低限、

```text
0
negative
max rank超過
```

を確認する。


を確認する。

## 8. training state

評価系APIはmixed training stateを使って確認する。

例：

```text
root = train
BatchNorm = eval
```

呼出前後で全`model.modules()`の`.training`が完全一致することを確認する。

対象：

```text
evaluate
agreement
benchmark_inference
collect_compression_metrics
```

例外発生時の復元もテストする。

## 9. DataLoader

### empty

```text
train_one_epoch
evaluate
agreement
logits_rmse
take_inference_batch
```

はemptyを明示的に拒否する。

### no-len IterableDataset

1回走査で完結するAPIでは `len(loader)` を必須にしない。

### one-shot iterator

`collect_compression_metrics()` は複数回走査するため未対応。この制約はテストで「対応している」と誤認しない。

## 11. compatibility

旧API名やlegacy keywordは、Core API v1中はcontract testで保持する。

```text

```

---

## 12. 変更時のテスト追加ルール

Public APIへ変更・追加を行う場合は、最低限次を行う。

```text
1. 正常系
2. 最小/最大境界
3. invalid type/value
4. 元model/stateへの副作用
5. return shape/structure
```

数学アルゴリズム変更なら、さらに、

```text
full-rank/known result
reference implementation比較
```

を追加する。

## 13. TT/MPS基礎API

### 表現とvalidation

```text
TT-SVD full-rank再構成
rank上限付き近似
bond別rank上限
逐次SVD step別tail normとTT-SVD実測誤差の上限関係
指定rankより数値rankが小さい場合の追加tailと実測誤差の上限関係
零Tensorの最低bond rank 1
physical shape / boundary込みrank / parameter count
empty core / ndim / boundary / adjacent bond / dtype / device
```

### canonical form

```text
左coreの列直交
右coreの行直交
dense再構成値の保存
任意center / d=1
sourceからtargetへの左右移動
入力coreとstorageを変更しない
invalid center / source / target
canonicality errorのsite数・dtype・device・非破壊性
float32 / float64の微小な非零Gram差を0と誤報しないこと
```

`tt_move_center`の直交性テストでは、先に`tt_canonicalize(cores, source)`で前提を作る。非canonical入力を渡して「前提を自動検証する」contractはテストしない。

### truncation / rounding

```text
単一bondのrank_before / rank_after
bond特異値とdense cut unfoldingの特異値一致
局所誤差とdense Frobenius誤差の一致
eps_relに対する全体誤差
eps_rel=0 / d=1 / exact zero
微小な非零値を零扱いしない
tail slackが全体特異値scaleへ引きずられない
0次元bool Tensor拒否
diagnosticsのkey・型・意味
```

極小・極大値では、二乗診断値`local_tail_sq`だけで成否を判断せず、非二乗の`local_error`と実際の再構成誤差も確認する。

### contraction / autograd

```text
dense内積・Frobeniusノルムとのfloat64一致
異なるbond rank間の内積
order / physical shape / dtype / device mismatch
非零点のdense経由gradient比較
小規模TTのgradcheck
零TTノルムのforward 0と有限gradient
float32の微小な正値で通常sqrtと一致
負値はValueError、NaNは伝播
極端なscaleでinf / 0 / NaNを黙って有限値へ丸めない
```

勾配確認は`grad is not None`だけで済ませず、全要素に対して`torch.isfinite(core.grad).all()`を確認し、値を比較できるケースではdense側のgradientとも照合する。

### 距離APIの扱い

`tt_distance_sq` / `tt_distance`はCore API v1へ含めない。したがって「未公開APIをテストから隠す」のではなく、`compression.__all__`とmodule属性に誤って再登場しないこと、および再導入時に[[90_src設計/07_既知の制約と拡張方針]]の品質条件を満たすことを確認する。

---

## 14. Core API freeze条件

Core API v1を最終確定する条件：

```text
Public API一覧と__all__が一致
設計書とsignatureが一致
contract testと記述が一致
全pytest green
git diff --check clean
```

設計書だけ更新してテストが追従していない状態ではfreeze完了としない。
