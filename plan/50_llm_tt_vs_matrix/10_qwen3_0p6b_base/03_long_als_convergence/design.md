## 1. 目的

1. M5 の ALS が、何掃引（sweep）で停止の条件を満たすか。
2. 予備実験の T2 に出た、初期値による Q_λ の約 6% の差（M3 から始めた本のほうが低い）が、長く回すと消えるか、残るか。
3. 本実験の掃引の上限と停止の規則を、根拠をもって決める。

新しい手法の比較も、判定の規則の変更もしない。

### 用語

- **ALS**：コアを 1 つずつ、残りを固定して最適化することを繰り返す方法全体。
- **掃引（sweep）**：ALS の中の 1 往復。コアを端から端まで 1 往復して、全部を 1 回ずつ更新する。T2（3 コア）では、コア 0 → 1 → 2 → 1 → 0 の 5 回の更新で 1 掃引。1 回更新するたびに、QR 分解で正準形の中心を隣に移す。
- **ソルバー**：M5 を計算するコード。外側は ALS の掃引、内側は各コアの局所方程式 H_k x = b_k を解く CG。CPU 版は `src/nn_compression/tt_mps/metric_tt.py`、GPU 版は `src/nn_compression/tt_mps/metric_tt_solver.py`。

## 3. ソルバー（回す前に固定）

- GPU、`precision="float32_refine"`（float32 で解いて float64 で直す）、`preconditioner="jacobi"`、`cg_tolerance_mode="fixed"`、`cg_relative_tolerance=1e-8`、`max_cg_iterations=500`、`max_refinements=5`。
- 根拠：`02_metric_tt_solver_benchmark` で、M3 から 5 掃引した Q_λ が CPU 版と表示桁まで一致し、17〜20 倍速かった。T2・50% の真ん中のサイトでも、局所残差が 1e-12 まで届いた（float64 の Jacobi-PCG は 500 回で 8.8e-7 に止まる）。
- 更新の受理：今と同じ（Q_λ が増える更新は棄却する）。

## 4. 定義

- **局所の停留性**：

  ```
  s_k = ‖b_k − H_k c_k‖₂ / max(‖b_k‖₂, ε)
  ```

  - 掃引の終わりの同じ状態から、**更新はせずに**、正準中心を各サイトに移して測り直す。s_max = max_k s_k。
  - **毎掃引**計算する（T2 なら HVP 3 回と QR 程度で、1 秒もかからない）。
  - 今ある `DeviceSweepRecord.local_gradient_norms` は、各サイトを更新する直前の相対残差で、掃引の途中のそれぞれ別の状態で測った値である（`metric_tt_solver.py` の `_solve_site`）。停止の判定にも、停留性の報告にも使わない。今の `gradient_tolerance` による停止（同ファイルの `run_metric_tt_als_on_device`）も、この値の最大値を使っているので使わない。
- **目的値の相対差**：

  ```
  δ_Q = |Q_λ,a − Q_λ,b| / min(Q_λ,a, Q_λ,b)
  ```

- **2 つの解の距離**（どれも相対距離で、二乗ではない。Ŵ はコアから復元した密行列）：
  - Frobenius：‖Ŵ_a − Ŵ_b‖_F / ‖W‖_F
  - G_λ の計量：d_Gλ = ‖(Ŵ_a − Ŵ_b) G_λ^{1/2}‖_F / ‖W G_λ^{1/2}‖_F
  - 正則化なしの G：上の式の G_λ を G にしたもの
  - 検証データでの出力の差：上の式の G_λ を、WT-2・C4 それぞれの Gram にしたもの
  - TT のコアどうしはゲージの自由度があるので、直接は比べない。

## 5. 停止の規則（回す前に固定）

| 停止の理由 | 条件 |
|---|---|
| `converged` | 掃引ごとの Q_λ の相対減少が **5 掃引続けて 1e-7 未満**、かつ **s_max ≤ 1e-6** |
| `max_sweeps` | **1,000 掃引**に達した |
| `local_solver_unresolved` | 局所の CG の最終残差（float64 で測ったもの）が 1e-8 に届かない更新が出た。そのときは、その局所問題を `max_refinements=10` で最初から 1 度だけ解き直す。それでも届かなければ止める |

- `local_solver_unresolved` で止めるとき、解けなかった候補は Q_λ が下がっていても**採用しない**。その掃引の中で先に受理した更新も含めて、失敗した掃引は捨て、**最後に完了した掃引の終わりの状態**（中心 0、s_k を測った状態）を最終状態にする。失敗した局所問題の残差・反復数・採用しなかった候補の Q_λ は、診断情報として別に保存する（§8）。
- s_max ≤ 1e-6 は数学的な収束の証明ではない。内側の CG（1e-8）より緩くとった、外側の停留性の**運用上の基準**である。
- 1,000 掃引で s_max が 1e-6 に届かない可能性がある（ベンチマークでは、記録の仕方は違うが、5 掃引目の局所残差が T2 で 1.6e-2、1 掃引あたり 2 割ほどしか減っていない）。その場合は `max_sweeps` になる。s_max の推移は報告する。
- 時間の上限は設けない（§11 の見積もりを大きく超えたら、止めて相談する）。

## 6. 検算（通らなければ止めて相談する）

1. ALS を始める前の Q_λ が、予備実験の `m5_initial_values.csv`（`q_lambda_before_als`）と相対 1e-10 で一致する。M4_retruncated は、予備実験と同じ関数で作り直す。
2. T2・50%・M3 の最初の 5 掃引の Q_λ が、`02_metric_tt_solver_benchmark/als_trajectory.csv` の `cuda_float32` と一致する。この差を「同じ条件で回し直したときの差」として記録し、0.1% より十分小さい（目安は 1e-6 以下）ことを確かめる。25% にはベンチマークがないので、検算 1・3 と局所残差で確かめる。
3. 単調性：Q_λ,s+1 ≤ Q_λ,s × (1 + 1e-10)。増える更新は棄却する作りなので、増えるとすれば QR の丸め誤差だけである。
4. 最終のコアを CPU の float64 で計算し直した Q_λ が、記録と相対 1e-10 で一致する。

予備実験の 50 掃引目（`m5_history.csv`）との差は、合否の条件にはせず、診断値として記録する。CG をより正確に解いても、途中の経路が変われば 50 掃引目の値が必ず小さくなるとは限らないため。差が大きければ、止めて原因を調べる。

### 6.1 実データでの試運転（本実行の前）

保存ファイルは `_smoke` を付けて本実行のものと分ける。

1. 4 本の初期値で検算 1。
2. T2・50%・M3 を 5 掃引回して検算 2。
3. 4 本とも 5 掃引ずつ回し、掃引あたりの時間、s_max の大きさ、解き直しの有無を見る。
4. 再開の確認（試運転のときだけ `checkpoint_every=2`。本実行は 50 のまま）：T2・50%・M3 について、
   - 中断なしで 5 掃引回す（`checkpoint_every=2`、`max_sweeps=5`）
   - 同じ規則で、2 掃引が終わって保存したあとに意図的に中断し、保存した状態から 5 掃引まで再開する
   - 2 本の、時間以外の記録と最終のコアが**ビット単位で一致**することを確かめる。GPU の計算が決定的であることは保証していない（`torch.use_deterministic_algorithms` は使わない）ので、一致しなければ最大の差を記録して止め、原因を調べる
5. 時間の内訳を分けて記録する：ALS 本体、s_k の計算、正則化なしの Q、検証データでの診断、保存。

## 7. 記録

| 頻度 | 量 |
|---|---|
| 毎掃引 | Q_λ、正則化なしの Q、相対減少、相対減少が続けて 1e-7 未満だった回数、s_k（全サイト）と s_max、更新ごとの CG の反復数と最終残差、外側の反復の回数、解き直しの有無、棄却数、時間（HVP、前処理、QR、受理判定、s_k の計算） |

| 最後 | δ_Q、§4 の 5 つの距離（Frobenius、G_λ、G、WT-2、C4）、最終の Q_λ の 0.1% 以内に初めて入った掃引数、50 掃引目の e・ρ と最終の値との差（ρ は予備実験の M2・M3 の e を使って計算し直す） |

## 8. 再開と保存

- 50 掃引ごとと停止時に、`utils.atomic_torch_save` で原子的に保存する。
- 保存する中身：全コア、終わった掃引の数、全履歴、相対減少が続けて 1e-7 未満だった回数、時間の累計、設定値、初期値の名前、入力ファイルのハッシュ。
- 再開したときは、設定値と入力のハッシュが一致することを確かめてから続ける。
- 正式な状態と、失敗した途中の更新は分けて保存する。
  - 正式な状態：全コアは、常に**最後に完了した掃引の終わり**のもの。終わった掃引の数も、完了した掃引だけを数える。
  - `local_solver_unresolved` で止めたとき：別の項目（`failure`）に、失敗した掃引・サイト、解き直す前と後の残差、反復数、外側反復の回数、失敗した更新の直前の Q_λ と採用しなかった候補の Q_λ、その掃引の中で行った更新の記録を入れる。
- 停止した保存ファイルから呼び直したときは、計算せずにそのまま結果を返す。

## 9. 判定（予算ごと。回す前に固定）

| 判定 | 条件 | 解釈 |
|---|---|---|
| `converged_equivalent_objective` | 2 本とも `converged` で、δ_Q < 0.1% | 予備実験の差は、収束が遅かったためと考えられる。同じ目的値でも、表す行列が違うことはありうる（§4 の距離で確かめる） |
| `converged_initialization_dependent` | 2 本とも `converged` で、δ_Q ≥ 0.1% | 初期値によって、異なる停留候補に行く。局所最小とは主張しない。本実験では初期値を複数にする |
| `max_sweeps_unresolved` | どちらかが `max_sweeps` | 結論を出さない。外挿は参考値にとどめる |
| `local_solver_unresolved` | どちらかが `local_solver_unresolved` | ALS の収束の問題とは分けて扱う |

- **判定の優先順**（上から順に当てはめる）：
  1. どちらかが `local_solver_unresolved` → `local_solver_unresolved`（たとえばもう片方が 1,000 掃引に達していても、ALS の収束より先に、局所問題を解けていないことを問題にする）
  2. それ以外で、どちらかが `max_sweeps` → `max_sweeps_unresolved`
  3. 両方が `converged` → δ_Q で 2 つに分ける（δ_Q < 0.1% なら `converged_equivalent_objective`、δ_Q ≥ 0.1% なら `converged_initialization_dependent`）
  4. それ以外の組み合わせ（知らない停止理由）→ 実装上の想定外としてエラーにする
- **判定関数の置き場所**：1 本の ALS をいつ止めるか（§5）は `tt_mps/metric_tt_solver.py` の `ConvergenceStopRule`。止まった 2 本を比べる判定は `metrics/als_convergence.py` の `classify_als_initialization_dependence`（2 つの停止理由と 2 つの最終 Q_λ から、判定と δ_Q を返す純粋関数）。0.1% は関数の中に埋め込まず、Notebook から `equivalence_tolerance=1e-3` として明示的に渡す。
- 0.1% に理論的な根拠はない。観測された約 6% の差を「ほぼ同じ」か「はっきり残る」かに分けるために、先に決めた「同等とみなす幅」である。「同じ解」の判定ではない。
- 追加の確認：`converged_initialization_dependent` になった予算だけ、M3 に小さい摂動を加えた初期値から 1 本足す。最初からは増やさない。摂動は次のとおり固定する（`tt_mps/metric_tt_solver.py` の `perturb_tt_matrix_site`、`site=1`、`relative_size=1e-2`、`seed=0`）。
  1. M3 を**中心 1**（真ん中のコア C_1）の混合正準形にする。
  2. C_1 と同じ shape のガウス雑音 Z を、CPU の float64 で seed 0 から作り、Frobenius ノルム 1 に正規化する。
  3. 中心のコアだけを変える：C_1′ = C_1 + 1e-2 · ‖C_1‖_F · Z / ‖Z‖_F
  4. 中心 0 の混合正準形に戻す（ゲージの変換だけで、復元行列は変わらない）。
  5. 実現した相対摂動 δ_W = ‖W̃_perturbed − W̃_M3‖_F / ‖W̃_M3‖_F を記録する。中心 1 の混合正準形では ‖ΔW̃‖_F = ‖ΔC_1‖_F、‖W̃‖_F = ‖C_1‖_F なので、δ_W は丸めを除いて 1e-2 になる。
  - 1% は「小さいが数値誤差ではない、前もって決めた診断用の摂動」であり、理論的な根拠はない。
  - 中心 0（サイト 0）のコアに摂動しない理由：ALS はサイト 0 から更新を始める。サイト 0 の局所問題はほかのコアを固定した狭義凸な 2 次問題なので、解はそのコアの初期値によらない。したがってサイト 0 への摂動は最初の更新で（CG の精度の範囲で）消え、診断にならない。小さい問題でも、1 掃引後の Q_λ の相対差はサイト 0 への摂動で 1.2e-16、サイト 1 で 2.7e-4、サイト 2 で 4.8e-4 だった（単体テスト `test_a_site_0_perturbation_is_erased_by_the_first_update_but_a_site_1_one_is_not`）。

### 14.3 判定（§9 の規則による。回す前に固定したもの）

| 予算 | 判定 | 理由 |
|---|---|---|
| 50% | `local_solver_unresolved` | M4_retruncated が局所問題を解けずに止まった（優先順の 1） |
| 25% | `max_sweeps_unresolved` | 2 本とも 1,000 掃引に達した |

- どちらの予算も、初期値への依存について結論は出さない。
- `converged_initialization_dependent` にならなかったので、摂動の 1 本は回していない（§9 のとおり）。
- まとめ：**1,000 掃引以内に、設計の収束の基準（相対減少が 5 掃引続けて 1e-7 未満、かつ s_max ≤ 1e-6）を満たした本はなかった**。Q_λ はほぼ横ばいになった（M3 は 410〜435 掃引目から、最終の値の 0.1% 以内）が、停留性の基準からは 2〜3 桁離れていた。50%・M4_retruncated は収束を判定する前に止まったので、「収束しなかった」ではなく「判定できなかった」。
- 言わないこと：「ALS は収束しない」（1,000 掃引で届かなかっただけ）、「Q_λ はもう下がらない」（M3 でも 1 掃引あたり相対 5e-7〜9e-7 は下がっている）、「2 つの初期値は同等」（判定の規則で確認できていない）。

### 14.4 解釈（Claude。仮説で、確かめてはいない）

1. **予備実験の 6% の差の大部分は、収束が遅かったためと考えられる**。同じ掃引数で比べて 0.4〜0.6% まで縮み、25% ではまだ縮んでいる。ただし判定の規則では確認できていない。
2. **1 サイトの ALS は、この問題では収束が非常に遅い**。s_max が掃引数にほぼ反比例して減るなら、1e-6 まで下げるには 10^5 掃引程度が必要になる。設計の s_max ≤ 1e-6 は、この方法と掃引数では現実的でなかった。
3. **目的値は近くても、解の行列はかなり違う**。G の計量での距離（0.25〜0.33）は、誤差の大きさ（√e ≈ 0.38〜0.52）と同じ程度で、Frobenius の距離は ‖W‖ を超える。G の固有値がとても小さい方向（予備実験で G の条件数は約 3e14、有効ランクは約 60）では、重みが λ の正則化以外でほとんど縛られないためと考えられる。収束していないためか、目的値がほぼ同じ解がたくさんあるためかは区別できない。
4. **50% が止まったのは、ALS の収束の問題ではない**。float32 で解いて float64 で直すとき、条件の悪い局所問題で残差が 1e-8 の近くで止まった、精度の限界に近い現象と考えられる。外側の s_max が 1e-3 程度のときに局所問題を 1e-8 まで解く必要があるかは、別に検討が要る。
5. **予備実験の結論への影響は小さい**。ρ は長く回しても 0.02 以下しか変わらない。較正での M5 の e は、50 掃引目から最終までに、M3 から始めた本で約 1%（50%：0.1462 → 0.1447）、M4_retruncated から始めた本で 6〜7%（50%：0.1554 → 0.1457、25%：0.2936 → 0.2740）下がった。予備実験で採用したのは Q_λ の低い M3 からの本なので、「本実験へ進む」という判定は変わらない。

### 14.5 予備実験の design.md §12.4 の注意点との関係

- 「全部 50 掃引で止まった（残りの減少の見積もり 0.2〜0.6%）」：1,000 掃引までの実際の減少は、M3 で 50 掃引目から 1.0%（50%）・1.0%（25%）で、見積もりより大きかった。
- 「T2 の初期値による Q_λ の差 約 6%」：上の 14.2 のとおり、長く回すと 0.4〜0.6% まで縮んだ（未収束）。

### 14.6 本実験の設計で決めること

追記（2026年11月8日）：停止の規則、局所ソルバーの扱い、GPU の作業の順番は確定し、`../04_main_experiment/design.md` に書いた（§3・§4・§6）。局所の許容誤差を緩める方法は、そちらの §6.4 で別に検証する。初期値の数は未決定。以下は、確定前に挙げた論点の記録。

- 停止の規則：s_max ≤ 1e-6 の代わりに何を使うか（掃引数の上限を 400〜500 にする、Q_λ の相対減少だけで止める、など）。根拠と限界を書くこと。
- 局所問題の許容誤差：外側の停留性に合わせて緩めるか（以前、5 掃引のベンチマークで adaptive は Q_λ が +0.04% だった）。
- アルゴリズム：1 サイトの ALS より速く収束する方法（2 サイトの更新、全体の前処理つきの勾配法など）を検討するか。
- 初期値：1 つで足りるか、複数にするか。
- GPU を使い切る作り：残差を CPU に取り出すのを数回に 1 回にする、独立した本を同時に回す、診断も GPU で計算する。
