## 要点

### 分析 0（既存の CSV から）

- C4 の $\rho$ の低下を、分子 $(e_{M5}-e_{M2})/e_{M3}$ と分母 $(e_{M3}-e_{M2})/e_{M3}$ に分けると、42 セルすべてで分子が増え（主な 34 セルの中央値 0.070 → 0.105）、分母が減った（0.83 → 0.76）。片方だけ C4 の値にすると、$\rho$ の中央値は分子だけで 0.92 → 0.87、分母だけで 0.92 → 0.91。主に分子。

### 分析 4：帯ごとの「M5 ÷ M2」（分析 1 の読み方の訂正）

分析 1 の「M5 − M2 の 68% が 257 位以降」は、「257 位以降で M5 が M2 の何倍も落とす」という意味ではない。帯ごとに比を測ると（主な 34 セルの中央値 [最小, 最大]、較正の重みつき）：

| 帯 | 1〜16 | 17〜64 | 65〜256 | 257〜 |
|---|---|---|---|---|
| M5 ÷ M2 | 4.58 [0.57, 21.5] | 4.01 [0.52, 10.9] | 1.59 [0.44, 3.88] | 1.35 [0.91, 2.06] |

- 倍率が大きいのは上位の帯。ただし M2 は上位の帯をほぼ完全に表すので、そこでの誤差の絶対値は小さく、差も小さい。
- 257 位以降は、M2 自身の誤差の大部分がある帯（低ランク近似が捨てる帯）。M5 はそこで M2 より 3〜4 割多く誤差を残す。もとが大きいので、それが M5 − M2 の大部分になる。
- 正しい言い方：「どちらも、較正データであまり来ない向きを大きく雑に扱う。M5 はそこで M2 より 3〜4 割多い。C4 はその向きに較正の 1.65 倍の入力を乗せるので、差が広がる」。「M5 だけが、M2 の保つ情報を落とした」ではない。
- 各帯に乗る較正データの入力の量（`input_share.csv`）：attention の入力では 1〜16 位に 62〜71%、257 位以降（768 本）に 9〜12%。down の入力（3072 次元）では 257 位以降に 28〜44%。257 位以降は、1 本ずつにはほとんど乗らないが、束では無視できない。
- 帯の区切り（16・64・256）は、03 で有効ランクが約 60 だったことから、その前後が分かれるように結果を見る前に決めた。別の区切りでの確認はしていない。

### 分析 7：同じ較正の目的で、M2 と M5 は誤差をどの向きに置いたか（ChatGPT の D・C）

**5. まれな向きでの残差の主な向き**

- 257 位以降の残差 $RP_{\text{tail}}$ の上位 10 個の右特異方向で、先頭の誤差（その帯の分）のうち 1〜9% しか説明できない。
- 「M5 の残差の少数の大きな向きに、先頭の入力が当たった」という説明は支持されない。M5 の誤差は、まれな向き全体に広く出ている。

**まとめ（推測を含む）**

- 同じ較正の目的でも、M2 はまれな向きで元の出力を削るだけ（相対誤差 < 1）だが、M5 はそこに元にない出力を足す（> 1）。目的への寄与は $\gamma_i$ が小さいので、どちらもほとんど同じ。
- 先頭の入力はまれな向きに偏り、元の $W$ はそれをほぼ 0 に写す。M2・M3 はこの「ほぼ 0」を保ち、M5 は保たない。これが先頭の相対誤差 4〜16 の正体。
- （推測）M5 がまれな向きに出力を足す理由は、TT の形（入力の添字を分けて持つ構造）では、よく来る向きを合わせた結果がまれな向きにも漏れ、目的がそれをほとんど罰しないため。M2（ランク制約だけ）は白色化した空間で切り捨てるだけなので、元にない出力を作りにくい。この理由はまだ測っていない。
- 検算：較正の寄与の和と直接計算の相対差 $1.2\times10^{-15}$、先頭の誤差の向きごとの和 $2.2\times10^{-16}$、tail の特異値の二乗和 $3.0\times10^{-13}$。
