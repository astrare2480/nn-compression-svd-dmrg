# 共通設計方針

## 1. 目的

このファイルは、圧縮方式に関係なく `src/nn_compression/` 全体で守る設計ルールを定義する。

---

## 2. Public API境界

各sub-packageの `__all__` をPublic APIの基本境界とする。

```text
Public API
→ Core API v1の互換性対象

private helper / __all__外
→ 外部contractを維持する限り変更可能
```

内部helperの配置や実装方法を固定しすぎず、利用側から見えるcontractを固定する。

---

## 3. baseline非破壊

圧縮処理でbaseline modelを暗黙に変更しない。

### model-level API

```text
baseline
→ deepcopy
→ copy側のlayerを置換
→ compressed model
```

### layer-level API

入力layerを変更せず新しいModuleを返す。

### 理由

- baseline/compressed比較を安全にする
- Fine-tuningでbaselineを壊さない
- 保存済みbaseline checkpointとの対応を維持する

---

## 4. device / dtype

新しいNN Moduleを作る圧縮APIは元layerのdevice/dtypeを維持する。

```text
CPU → CPU
CUDA → CUDA
float32 → float32
float64 → float64
```

意図しないCPU移動やfloat32固定を行わない。

### Tucker/HOOI decomposition dtype

現行のHOSVD/HOOI分解アルゴリズムは**実数浮動小数点Tensor**を正式対応範囲とする。

```text
floating real Tensor
→ supported

complex
integer
bool
→ decomposition入口でTypeError
```

複素数対応を行う場合は、`U.T` と共役転置 `U.mH` の扱いを含めて別途設計する。

---

## 5. `requires_grad` とautograd境界

### Module factorization

既存layerを圧縮Moduleへ変換するときは、元weightから新しいParameterの初期値を作る。

```text
original Parameter
→ detach
→ decomposition
→ no_grad copy
→ new leaf Parameters
```

元layerの `requires_grad` 設定は生成Moduleへ引き継ぐ。

### Tensor-level decomposition

`hosvd()` / `tucker2_hooi()` 等の低レベルTensor処理では、必要以上にdetachしない。

Tensor-level APIとModule constructionのgraph境界を混同しない。

---

## 6. validation方針

invalid inputをPyTorch内部の偶発的なエラーへ流さず、Public API境界で意味のある例外にする。

### rank

```text
bool拒否
Tensor scalar拒否
整数scalar
数学的最大rank以内
```

### mode

```text
bool拒否
int
0 <= mode < ndim
```

### Tensor shape

Tucker/tensor mode演算では、

```text
ndim >= 2
各dimension > 0
```

を基本contractとする。

### tolerance

```text
finite
>= 0
bool拒否
```

### benchmark count

```text
warmup >= 0
repeats >= 1
bool / Tensor scalar拒否
整数scalar
```

---

## 7. rankを黙ってclampしない

指定されたrankが数学的上限を超える場合、

```text
requested rank → silently max rankへ変更
```

は行わない。

明示的な `ValueError` とする。

理由は、実験者が意図したrankと実際に使われたrankがずれると、保存結果や比較の意味が壊れるため。

---

## 8. train/eval state

評価・比較・benchmarkは一時的に `eval()` を使う。

処理終了後は、rootの `model.training` だけでなく、全submoduleのtraining flagを元に戻す。

例：

```text
root = train
BatchNorm = eval
```

という混合状態を壊してはならない。

正常終了だけでなく例外時にも復元する。

`train_one_epoch()` は学習APIなのでこの復元contractの対象外で、`model.train()` を設定する。

---

## 9. DataLoaderと乱数状態

候補比較・評価で学習用shuffle Generatorを不用意に消費しない。

### 推奨

```text
train_loader
→ shuffle=True
→ optimizer update専用

train_eval_loader
→ shuffle=False
→ train metric取得
```

### latency input

baseline/compressedには同じinput Tensorを渡す。

`take_inference_batch()` はshuffle付きRandomSamplerを拒否する。

---

## 10. empty input

空DataLoaderを偶発的な0除算へ落とさない。

```text
train_one_epoch
evaluate
agreement
logits_rmse
take_inference_batch
```

等ではemptyを明示的にエラーにする。

`len(loader)` を前提にせず、IterableDatasetを1回走査できるAPIでは実走査結果で判定する。

---

## 11. 理論値と実測値を分ける

```text
parameter reduction
MACs reduction
latency reduction
```

は別指標である。

MACsは主要な積和回数の理論値であり、

- memory access
- kernel launch
- activation
- framework overhead

等を表さない。

したがって「MACsが減ったから速い」とAPIや設計書で同一視しない。

---

## 12. compatibility

historical Notebookの再現性のため一部旧名を残す。

```text
SVD
RebuildSVD
factorize_Conv2d_layer
factorized_*_macs
sweep_conv_svd_ranks
r1 / r2 keyword
```

新しいコードではprimary APIを使用する。

互換APIは新機能の追加先にしない。

---

## 13. experiment-specific値の扱い

srcへ埋め込まない：

```text
selected rank
seedごとの最終accuracy
CSV名
checkpointファイル名
```

ただし既存モデル構造やFashion-MNIST向けhelper等、過去Notebook再現のため明示的にexperiment-support APIとして残すものはある。

---

## 14. 内部refactor

Core API v1固定後も次は可能。

```text
private helper統合
validation helper移動
内部高速化
type hint改善
comment/docstring改善
test追加
```

ただし、

```text
signature
return structure
主要例外
shape convention
autograd/state semantics
```

を変える場合はbreaking changeとして扱う。

---

## 15. 新方式追加

TT/MPS・DMRG追加では、既存関数へ多数のif分岐を追加して万能化しない。

```text
既存共通機能
→ 再利用

新方式固有の数学・rank構造
→ 新しいAPI
```

を基本とする。
