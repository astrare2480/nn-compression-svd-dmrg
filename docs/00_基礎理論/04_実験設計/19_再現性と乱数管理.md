# 再現性と乱数管理

## サマリー

SVD圧縮実験では、rank候補ごとの差が小さいことがある。

そのため、

```text
モデル差
```

と、

```text
乱数による学習条件差
```

をできるだけ分離する必要がある。

今回のcorrected実験で重要だったのは、単に `torch.manual_seed(SEED)` を1回呼ぶことではなく、**乱数を用途ごとに分け、候補間で同じ条件を再現すること**だった。

---

# 1. 乱数は1種類ではない

学習では、複数の場所で乱数が使われる。

```text
weight初期化
Dropout
DataLoader shuffle
RandomCrop
RandomHorizontalFlip
train / validation split
candidateごとのFine-tuning
```

全部を1つのグローバル乱数状態へ依存させると、途中で乱数を使う処理を追加しただけで、後続の実験条件が変わり得る。

したがって、用途を分離する。

---

# 2. データ分割用Generator

train / validationの分割は、専用Generatorで固定する。

```python
split_generator = torch.Generator().manual_seed(SEED)
indices = torch.randperm(
    dataset_size,
    generator=split_generator,
)
```

こうすると、

```text
weight初期化で乱数を使った
Dropoutを追加した
別のshuffle処理を追加した
```

といった変更があっても、split用Generatorを同じ順序で使う限り、データ分割を独立に再現しやすい。

---

# 3. DataLoader用Generator

`shuffle=True` のtrain DataLoaderは、mini-batch順を決めるために乱数を使う。

```python
loader_generator = torch.Generator()
loader_generator.manual_seed(SEED)
```

として、DataLoaderへ渡す。

```python
train_loader = DataLoader(
    train_dataset,
    shuffle=True,
    generator=loader_generator,
    ...,
)
```

candidate A / B / Cを公平に比較したい場合は、各candidateのFine-tuning前にseedとloader Generatorを同じ状態へ戻す。

```text
Candidate A
seed = 0
shuffle sequence = S

Candidate B
seed = 0
shuffle sequence = S

Candidate C
seed = 0
shuffle sequence = S
```

こうすることで、candidate差にmini-batch順の差が混ざることを減らす。

---

# 4. 評価でtrain loaderを再走査してはいけない理由

corrected実験で重要だった修正の1つ。

学習用 `shuffle=True` DataLoaderを、train accuracyなどの**評価目的で追加でもう1回走査**すると、そのloaderのGenerator状態が進む。

すると次回の学習で、

```text
本来のshuffle sequence
```

ではなく、評価で乱数を消費した後のsequenceを使うことになる可能性がある。

結果として、

- 次epochのmini-batch順
- 次candidateのmini-batch順

が変わる。

これは、評価処理そのものが後続学習へ介入することになる。

---

# 5. `train_eval_loader` / non-shuffling loader

そのため、train指標を測る場合は、学習用shuffle loaderとは別に、同じDatasetを `shuffle=False` で読むloaderを使う。

```text
train_loader
→ 学習専用
→ shuffle=True

train_eval_loader
→ train指標の評価専用
→ shuffle=False
```

現在の共通実装では、この意図を `non_shuffling_loader` と `train_eval_loader` で表している。

重要なのは、train accuracyを測ること自体ではなく、**評価がtraining RNG stateを進めないこと**。

---

# 6. augmentationの乱数

CIFAR-10では、

- `RandomCrop`
- `RandomHorizontalFlip`

も乱数を使う。

したがって、同じ元画像でも学習中に異なるTensorが生成され得る。

これは学習用augmentationとして意図した挙動。

一方、validation / testではランダムaugmentationを外し、同じindexから同じ評価Tensorを得られるようにする。

```text
train
→ ランダム性あり

validation / test
→ 入力条件固定
```

詳細は [[30_CIFAR10_CNN/00_CIFAR10基礎/18_CIFAR10の前処理とDataLoader]] を参照。

---

# 7. candidate Fine-tuningの公平性

rank候補をFine-tuningするとき、次のような実験は避ける。

```text
Aを学習
↓ RNGが進む
Bを学習
↓ RNGがさらに進む
Cを学習
```

この方法だとcandidateごとに、

- Dropout mask
- shuffle順
- その他の乱数系列

が異なる。

candidateのrank差を見たいなら、各候補の開始前に条件を揃える。

```text
for candidate in candidates:
    set_seed(SEED)
    loader_generator.manual_seed(SEED)
    model = rebuild(candidate.rank)
    fine_tune(model)
```

これにより、比較対象をできるだけrank差へ限定する。

---

# 8. baselineとcompressed modelはParameterを共有しない

再現性とは少し違うが、公平な比較の前提として重要。

圧縮モデルがbaselineのmodule / Parameterを共有していると、compressed modelをFine-tuningした際にbaselineまで変化してしまう。

```text
baseline
└─ Parameter A

compressed
└─ 同じ Parameter A  ← NG
```

これでは「Fine-tuning前のbaseline」と「Fine-tuning後のcompressed」を比較しているつもりでも、baseline自体が変更済みになる。

現在の実装では `deepcopy` と新しいfactor layer生成により、baselineとcompressedを分離する。

---

# 9. train / validation / testの役割

再現性だけでなく、実験の妥当性も分離する。

```text
train
→ パラメータ学習

validation
→ rank選択
→ candidate選択
→ Early Stopping
→ Fine-tuning条件比較

test
→ 最終モデル決定後の確認
```

rank sweepの途中でtest accuracyを見てrankを選ぶと、testが実質的にvalidationとして使われてしまう。

corrected MNISTでは、rankをvalidationで決め、testは選択した1組だけ評価した。

---

# 10. 同じseedでも完全に同一とは限らない

seed固定は、常にビット単位の完全再現を保証するものではない。

結果は、

- PyTorch version
- torchvision version
- CUDA / cuDNN
- GPU
- 使用algorithm
- deterministic implementationの有無

などにも依存し得る。

したがって、実験ログには少なくとも、

```text
SEED
Python / PyTorch / torchvision
CUDA / cuDNN
GPU
train / validation split条件
DataLoader batch_size / shuffle / num_workers
transform
model定義
optimizer / learning rate
SVD対象層 / rank
```

を残す。

---

# 11. single seedの解釈

今回のcorrected SVD実験は基本的にsingle seedである。

そのため、例えば、

```text
Baseline acc = 0.9128
Compressed = 0.9175
```

のような小さな差が出ても、

> SVDにより統計的にaccuracyが改善した

とは言わない。

中心となる解釈は、

> **圧縮後もaccuracyをほぼ維持した**

である。

複数seedで平均・標準偏差を取って初めて、小さい差の頑健性を議論しやすくなる。

---

# 12. 実験コード側で守る不変条件

今回の修正を一般化すると、次を守る。

```text
1. split RNGとtraining RNGを分ける
2. candidate間でseed条件を揃える
3. 評価でtraining DataLoader Generatorを進めない
4. baseline / compressed Parameterを共有しない
5. validationで選び、testは最後に使う
6. single seedの小差を過大解釈しない
```

この背景は、[[05_SVD基礎実装検証/03_SVD実験で修正した問題と設計原則]] に問題→原因→修正→影響の形でまとめている。
