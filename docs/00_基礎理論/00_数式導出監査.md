# 数式導出監査

## 目的

基礎理論ノートに現れる非自明な式について、**最終式だけを置かず、どの式からどう変形したかを追える状態**にする。

今回の監査では、過去に添付された次の資料を主な根拠として再確認した。

```text
DMRGとかSVNをNNに適用してNNの縮小化と精度の維持を図りたい_最終版.pdf
Fashion-MNISTにSVDをあてる.pdf
CNN CIFAR-10→Tuckerを考える.md
```

実験値は現在の `results/` CSV と各canonical Notebookを優先する。

## 記載ルール

式を使うときは、必要に応じて次の順序を残す。

```text
定義
→ shape / 次元
→ 代入前の一般式
→ 途中の積・和・変形
→ 最終式
→ 今回の具体的な数値代入
→ その式が意味すること
```

同じ導出を多くのノートへ完全複製すると、後で一部だけ修正されて不整合になりやすい。そのため、長い導出は次の2ファイルをcanonical derivationとし、各テーマのノートでは必要な途中式をローカルに残しつつ参照する。

- [[00_基礎理論/01_数学基礎/01_線形代数/02_SVD数式の導出]]
- [[00_基礎理論/01_数学基礎/02_テンソル代数/20_Tucker_HOSVD_HOOI数式の導出]]

## 実験検証ノートの監査

`06_Tucker基礎実装検証` は今回、最終値だけでなく次の算術を明示した。

- HOSVD error − HOOI error
- 相対改善率
- 元Conv/Tucker-2のweight数の内訳
- parameter reductionの分子・分母
- accuracy dropの符号
- HOSVD/HOOI fine-tuning前後の回復量
- fine-tuning後weight errorの増分
- single seedの差をpercentage pointへ換算

## 方針

「途中式」は、単に式を細かく分割することではない。少なくとも、**なぜその分母になるか、なぜ転置するか、どのshape同士を掛けているか、何を相殺したか、何を固定して何を更新したか**が追えることを基準にする。

今後TT/MPS・DMRGを追加するときも同じ基準で、

```text
reshape / tensorization
→ 行列化
→ SVD
→ truncate
→ core shape
→ 再構成
→ error
→ parameter count
```

を途中式込みで残す。
