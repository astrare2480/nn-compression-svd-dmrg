## 1. 問いと位置づけ

### 問い
同じ保存量の上限と、同じデータ計量のもとで、学習後の TT 圧縮が行列の低ランク圧縮に負けるのは、

- 通常の TT-SVD が、目的関数を誤っているから（重み行列のずれを最小化していて、出力のずれを見ていない）なのか、
- TT という表現そのものの制約によるのか。

### 誤差の分解（概念）
E_TT-SVD − E*_Matrix = (E_TT-SVD − E*_TT) + (E*_TT − E*_Matrix)

- 第1項：目的関数・初期化・最適化手順による差
- 第2項：同じ費用での、TT という表現と行列低ランクという表現の差
- **注意**：E*_Matrix は白色化した SVD で厳密に求まるが、E*_TT は ALS で得た上界にすぎない。そのため第2項は大きめに出る。「TT 表現の限界」を断定する根拠にはできない。

### この予備実験の役割
本実験（複数の層・モデル）に進むかどうかを判定するためのもの。論文の最終結論にはしない。
0.6B・1モデル・1層の結果なので、「現在の LLM 一般に当てはまる」とは言えない。「現在の構造（SwiGLU・RMSNorm）のモデルで見込みを確認できる」までである。

### 関連する先行研究（詳細は議論の記録を参照）
- arXiv 2606.03465v1（Zagitov et al., 2026, "Rethinking the Role of Tensor Decompositions in Post-Training LLM Compression"。Perplexity による原典確認、2026年11月7日）：
  - 結果：GPT-J 6B・LLaMA 2 7B などで、TT は同程度のモデル保存量で行列の手法より perplexity が悪い（例：図7、C4 で約19 対 約28超）。
  - TT 側：12コアの TT-matrix、rank の上限 64、TT-SVD（フロベニウス誤差）。圧縮後の LoRA 補修と Dense-Sparse TT（重要な要素を残す）はあるが、**データの計量でコアを直接最適化する方法（今回の M5 に当たるもの）はない**。
  - 行列側：普通の SVD（LASER）と、データを考慮した手法（Dobi-SVD、SoLA、FLAT-LLM、HASSLE-free）。疎な成分や rank 配分を含むものが多く、純粋な白色化 SVD（M2）とは違う。SVD-LLM は引用だけで比較なし。
  - **層ごとのパラメータ数はそろえていない**（表3：FFN の1層で局所圧縮率が TT 398倍、LASER 2.9倍）。横軸は埋め込みを除くモデル全体の保存量。
  - §4 に「フロベニウス誤差の重みづけやモードの並べ替えでは解消できない」という主張がある。ただし根拠は作用素ノルムについての誤差比の**上界**（式(7)）で、G を含まず、データで重みをつけた TT の実験もない。
  - この予備実験との関係：**層ごとに予算をそろえ、同じデータ計量のもとで TT のコアを直接最適化して比べる**のは、この §4 の主張を直接検証することにあたる。
  - 注意：tensorization が違う（先行研究は12コア、今回は3〜4コア。1024 = 2¹⁰ なので Qwen3 の入力は最大10コア）。結果は「3〜4コアでは」と限定して書く。M5 が e の差を縮めても perplexity の差が残る場合は、著者の作用素ノルムの議論を部分的に支持する結果として扱う。
  - 引用するときは「重みづけでは直らないことが証明された」とは書かない。
  - 未確認：付録の後半、参考文献の全件（AWT・FWTTM を引用しているか）。
- FWTTM（PACLIC 2023）：Fisher で重みをつけた TT と行列 SVD の比較。勝敗は条件次第。
- FTC（arXiv 2610.00717, 2026）：全二次モーメントを使う共有 Tucker が、同じ計量の行列手法に勝つ（数値は原典で要確認）。
- AWT（arXiv 2610.10085, 2026）：対角の重みの TT。全共分散は較正データでは強いが、別データでは負けることが多い（過適合の可能性）。

## 2. 対象とデータ

### 対象
- モデル：`Qwen/Qwen3-0.6B-Base`（28層、hidden 1024、MLP の中間 3072、SiLU、RMSNorm、bf16、埋め込みと出力層の重みを共有）。Instruct ではなく Base を使う（perplexity の評価をそのまま意味のあるものにするため）。
- 層：`model.layers[14].mlp.up_proj`（1024 → 3072）。**番号は 0 から数える。**
  - MLP の構造：u = W_up x、g = SiLU(W_gate x)、y = W_down (g ⊙ u)。`gate_proj` と `up_proj` は同じ入力 x を受けるので、G は共通。
  - `up_proj` を選ぶ理由：圧縮する層の出力自体には活性化関数がかからない。入力が 1024 次元で G を扱いやすい。ただし実際には gate との積を通して効くので、§5 の E_gated を補助の指標として記録する。
- 重み：`nn.Linear` の重みは (出力, 入力) の向きなので、そのまま W ∈ ℝ^{3072×1024}。バイアスはない（実装時に確認する）。
- 重みの精度：元の重みは bf16。float64 に変換してから最適化する（float64 にしても、bf16 で失われた精度は戻らない）。
- 入力 x：`up_proj` の forward pre-hook で、層に実際に渡された入力を取り出す（`post_attention_layernorm` の出力に相当するが、実装の違いに左右されないようにするため）。
- 埋め込みと出力層の重みの共有：MLP の1層だけを置き換えるので、直接の影響はない。保存や再読み込みのときに共有を壊さないよう注意する。

## 3. 予算（パラメータ数の上限）

密行列の重みは 3,145,728 パラメータ（3072 × 1024）。

| 予算 | 上限 | 行列の rank r（r(m+n) ≤ 上限、m+n = 4096） | 位置づけ |
|---|---|---|---|
| 50%（2倍圧縮） | 1,572,864 | 384 | 主条件 |
| 25%（4倍圧縮） | 786,432 | 192 | 主条件 |
| 16.7%（6倍圧縮） | 524,288 | 128 | 主条件で見込みがあった場合だけ追加 |

- 行列のパラメータ数：P_matrix(r) = r(m + n)（バイアスなし）
- TT のパラメータ数：P_TT = Σ_k r_{k-1} m_k n_k r_k
- TT の rank：上限 r で一様にそろえ、両端の bond は構造上の最大値で頭打ちにする。予算を超えない最大の r を選ぶ。tensorization ごとに独立に決める。
- 「同一費用」ではなく「同一の上限予算」と書く。**実際のパラメータ数を必ず併記する。**
- M4・M4b は、対角スケールの 1,024 個もパラメータ数に含める。
- パラメータ数と、理論上の積和演算数（MACs）は分けて報告する（主はパラメータ数）。

## 4. Tensorization と比較する方式

### Tensorization（事前に固定する）
- T1：4コア。リポジトリの `ordered_factorizations` と `tt_matrix_shape_imbalance` で、mode の偏りが最小のものを機械的に選ぶ。
- T2：3コア。同じ基準で選ぶ。
- 選び方は較正データだけに基づき、検証データを見て選び直さない。
- 1,024 個の入力特徴の並び順は元のまま。並べ替えはしない（限界として記録する）。

### 計量
- 入力の Gram 行列（平均を引かない二次モーメント。「共分散」とは呼ばない）：G = Σ_t x_t x_tᵀ（較正トークンから作る）
  - 平均を引かない理由：目的 E‖(W − W̃)x‖² が、平均を引かない二次モーメントで決まるため（正規化が RMSNorm かどうかとは関係ない）。
- 正則化した計量：G_λ = G + λ · tr(G)/1024 · I、**λ = 1e-6 に事前に固定**
- 最適化に使う目的関数：Q_λ(W̃) = ‖(W − W̃) G_λ^{1/2}‖_F²
- 報告に使う値：較正データでは正則化なしの G での値、検証データでは各データの活性化から直接計算した値
- λ を途中で変えない。変えるなら、M2 と M5 を両方やり直して別条件として記録する。

### 比較する6方式
| 方式 | 内容 |
|---|---|
| M1 通常の行列 SVD | W を rank r に切る |
| M2 白色化した行列 SVD | W G_λ^{1/2} を SVD で rank r に切り、G_λ^{-1/2} を掛けて戻す。Q_λ のもとで、rank r の行列として厳密に最適（基準値） |
| M3 通常の TT-SVD | 既存の `dense_to_tt_matrix_cores` |
| M4 Diagonal-RMS metric TT | s_i = sqrt(G_ii / N) とし、D = diag(s) で W D を TT-SVD したあと、D⁻¹ を掛けて戻す。推論は (TT, D⁻¹) の組で行う |
| M4b AWT-Std（補助） | AWT 原典の Std の重要度（正規化、α = 1、下限の clamp を含む）で M4 と同じ処理。**式は AWT 原典 §4 の式(5)・(6)に従う（実装時に原典で確認）** |
| M5 全計量の TT | 1サイトの固定 rank ALS で Q_λ を最小化する（§6）。M3 から開始したものと M4_retruncated から開始したものの2通りを実行し、**較正データの Q_λ が小さい方を採用する**（事前の規則。同点なら M3） |

- **M4_retruncated（2026年11月7日、実装レビューで確定）**：一般の対角 D⁻¹ は、bond 次元を変えずに TT のコアへ吸収できない（各コアの積の形になっていないため）。そこで、M4 の密行列 W̃_M4 を同じ rank でもう一度 TT-SVD したものを、M5 の2つ目の初期値にする。M4 そのものではないので、ALS 開始前の Q_λ を M4 の Q_λ と並べて記録する。
- **較正量の感度確認（同日確定）**：T2 だけ、予算 50%・25%、較正は先頭16系列。方式は M2 と M5（初期値は主実験で採用された方だけ）。G と G_λ は16系列から作り直す。判定には使わない。
- **T1 の性質（同日、実装結果から判明）**：T1 の mode は出力 (2, 2, 24, 32)、入力 (16, 16, 2, 2) で、rank は 50% で (32, 382, 64)、25% で (32, 190, 64)。両端の bond は構造上の最大値なので圧縮されておらず、**T1 は実質的に中央の1か所だけで切った近似**（並べ替えた行列の低ランク近似とほぼ同じ）。複数か所を切る TT になっているのは T2（rank (109, 109)・(77, 77)）。結果の解釈ではこの違いを明記する。

## 5. 評価の指標

- 相対出力誤差：E_rel = ‖(W − W̃) X‖_F / ‖W X‖_F
- 二乗誤差：e = E_rel² = Q / ‖W X‖_F²
- **gate を通した出力の二乗誤差（補助の指標。最適化にも判定にも使わない）**：
  E_gated² = ‖SiLU(W_gate X) ⊙ [(W − W̃) X]‖_F² / ‖SiLU(W_gate X) ⊙ (W X)‖_F²
  - W_gate は圧縮しない元の値を使う。
  - 「層の出力としては近いが、実際の SwiGLU の経路では大事な成分を壊している」場合を検出するためのもの。
- 計算するデータ：較正、同じドメインの検証、別ドメインの検証
- 1層置換の perplexity：WikiText-2 validation（補助の指標）
  - Base モデル、chat template なし、`model.eval()`、トークンのずらし方を明示。
  - tokenizer、系列の分け方、stride、評価するトークン数、cache の有無を全方式で固定する。
  - 方式の選択には perplexity を使わない。
- ブートストラップ：文書単位で再標本化（1,000回、seed 0）し、e の差の95%区間を出す

## 6. M5 の解き方

### 6.1 基本
- 正準形を保ちながら左右に掃引する、1サイトの固定 rank ALS。
- 局所の方程式 H_k c_k = b_k は、行列を作らずに、前処理つき共役勾配法（PCG）で解く。
  - 前処理は Jacobi（対角）から始める。
  - 「H_k を掛ける操作」は、ヘッセ行列とベクトルの積（HVP）で実装する。Q_λ は二次関数なので、HVP は正確に計算できる。
  - 可能なら、密行列 W̃ を毎回作らず、左右の環境と G_λ の縮約で HVP を計算する。

### 6.2 理論的な性質（Claude の導出。実装時に小さい問題で数値確認すること）
- 正準形では、左右の環境が正規直交になり、コアから W̃ への写像 P は長さを保つ（等長）。
- そのため、局所のヘッセ行列は H_k = Pᵀ (G_λ ⊗ I) P となり、**λ_min(H_k) ≥ λ_min(G_λ) > 0**。H_k は必ず正定値で、条件数は G_λ の条件数を超えない。ゲージの自由度による零固有値は生じない。
- 直前の値から開始した CG は、反復ごとに局所の Q_λ を単調に減らす（丸め誤差を除く）。
- 局所の正規方程式は K_k ⊗ I_{m_k} の形になる（出力の mode ごとに同じ K_k の方程式）。**この構造は、小さい問題で明示的なヘッセ行列と一致することを確かめてから、ブロック CG に使う。** それまでは HVP の実装を正とする。

### 6.3 停止と更新の受理
- CG：相対残差 1e-8、または 500 反復で止める。
- 掃引：Q_λ の相対減少が 1e-6 未満、または 50 回で止める。
- 更新の受理：更新後に較正データの **Q_λ** を計算し直す。減っていれば受理し、増えていれば棄却して元のコアに戻す（記録はする）。正則化なしの Q では判定しない（最適化の規則と矛盾するため）。
- 停止の判断は較正データの Q_λ だけで行い、検証データは見ない。

### 6.4 数値精度
- 重み：bf16 の元の値を float64 に変換して使う。
- Gram 行列、固有値、ALS の診断、最適化は CPU の float64 で行う（LLM の層の入力には外れ値のチャネルがあり、G が悪条件の可能性があるため）。GPU では float64 の計算をしない（一般向けの GPU は float64 が遅いため）。
- perplexity の評価は、**元のモデルも含めて全方式を GPU の float32 で行う**。圧縮した重みを bf16 に戻さない（bf16 の丸め誤差は相対で約 2⁻⁸ あり、方式どうしの差を埋もれさせるおそれがあるため）。

### 6.5 計算時間の事前計測（本実行の前に必須）
- 条件：T2、予算 25%、1コア、CG 10反復、半分の掃引1回
- これで全体の時間を見積もる。重すぎる場合は止めて相談する（λ や停止条件を勝手に変えない）。
- 事前の概算（Claude、未測定）：HVP 1回は約 6 GFLOP で、数十ミリ秒。最悪の場合（CG 500反復・掃引50回）で1条件あたり約1時間強、全体で10〜20時間程度。
- CG が極端に遅い場合の候補：G_λ^{1/2} を使った LSQR・LSMR（最初からは実装しない）。

### 6.6 計算機
- GPU：RTX 5070 Ti（16GB）。RAM：64GB。CPU：Ryzen 7 9800X3D（8コア16スレッド）。
- 事前の概算（未測定）：GPU は float32 のモデルと perplexity の評価で 5〜8GB 程度。RAM は活性化の保存で数GB 程度。

## 9. 判定の規則（結果を見る前に固定する）

### ρ の定義
g = e(M3) − e(M2)、ρ = (e(M3) − e(M5)) / g

- 較正データと検証データで、それぞれ別に計算する。
- ρ < 0 や ρ > 1 も丸めずに報告する。
  - ρ < 0：M5 が M3 より悪い
  - ρ > 1：M5 が、同じ予算の rank r の行列（M2）より良い。表現の種類が違うので、理論上ありうる
- **ρ を計算対象外とする条件**：g ≤ 0、または g の95%区間（ブートストラップ）が0をまたぐ、または g / e(M3) が最小値（D5、案 0.05）未満。この場合は `rho_status = denominator_not_informative` とする。
- ρ が計算できない場合も、次の量は報告する。
  - Δ_TT = e(M3) − e(M5)
  - R_M5 = e(M5) − e(M2)
  - κ = (e(M3) − e(M5)) / e(M3)
- **判定には e（gate を通さない層の出力の誤差）だけを使う。** E_gated から同じ式で計算した ρ_gated は報告だけにし、判定には使わない。e と E_gated で結論が食い違う場合は、レビューで指摘する。

### 判定（しきい値は D4 で確定する。案：0.2 と 0.5）
| 判定 | 条件 |
|---|---|
| 中止 | どの予算・tensorization でも、検証データで ρ < 0.2 |
| 過適合が主な結果 | 較正データでは ρ ≥ 0.5 だが、検証データでは ρ < 0.2 |
| 本実験へ進む | **同じ tensorization** が、両方の予算・両方のドメインの検証データで ρ ≥ 0.5 |
| 判定保留 | 上のどれにも当てはまらない場合（ρ が 0.2〜0.5、ドメイン間で不一致、ρ が計算対象外、CG が収束しない、など） |

- 0.2 と 0.5 は、予備実験の進退を決めるための工学的な目安であり、統計的な有意性や研究の成功基準ではない。
- 結果を見てからしきい値や規則を変えない。
- 「中止」と「過適合が主な結果」の両方の条件を満たす場合は、**「過適合が主な結果」とする**（2026年11月7日、結果を見る前に確定）。

### 判定後の行動
- 中止：A の方向性は予備実験で止める。結果は記録として残す。
- 過適合が主な結果：M4（対角）との比較をまとめ、拡張しない。
- 本実験へ進む：まず同じ層の `down_proj`（3072 → 1024。G が 3072×3072 になり重い）、次に別の位置（前・中・後のブロック）や attention の層へ広げる。第2のモデルは Pythia-410M（1024 → 4096、学習データ公開）を候補とする。その後、16.7% の予算、複数層の置換へ進む。
- 判定保留：原因（どの条件で、何が不一致か）を整理してから、追加するか止めるかを相談する。

### 12.3 解釈（仮説。この 1 層・1 射影の範囲）

- 学習後の TT 圧縮が行列の低ランク圧縮に負ける分（e(M3) − e(M2)）の 8〜9 割は、目的関数（Frobenius 誤差の TT-SVD）を計量つきに変えることで埋まる。負けの主因は目的関数で、表現の限界ではない。
- ただし、表現による損（e(M5) − e(M2)）も統計的にはっきり残る。切り口の多い TT（T2）、小さい予算（25%）、ドメインのずれ（C4）で大きくなる。
- データを使った TT（M5）は、データを使わない行列（M1）より良い。圧縮の形式より、データを使うかどうかの影響が大きい。

### 12.4 注意点（判定の後に分かったこと）

1. **T1 は実質的に 1 か所だけで切った TT**（ranks 32, 382, 64）で、行列の低ランク分解に近い。T1 の ρ が高いのは当然に近い。複数か所を切る TT は T2（ranks 109, 109）だけで、T2 は ρ が低めで M2 との差も 2〜3 倍。本実験では T2 型の TT を中心に見る。
2. **局所 CG の未収束**：採用した本（M3 から開始）のうち、T2・50% では中央のサイトの更新 100 回すべて（250 回中）が CG の上限 500 回に達し、相対残差は最大 3.5e-6（目標 1e-8）。感度確認の T2・50% も同じ。T1 と T2・25% の採用した本は、すべての更新が 1e-8 に届いた。M4_retruncated から始めた本では、T1 で更新の半分以上が上限に達した（残差は最大 3.6e-4）。棄却された更新はない。§9 は「CG が収束しない」を判定保留の例に挙げているが、T1 だけで「本実験へ進む」の条件を満たすので、判定は変わらない。
   - 追記（2026年11月8日、GPU 版ソルバーのベンチマーク。`results/50_llm_tt_vs_matrix/10_qwen3_0p6b_base/02_metric_tt_solver_benchmark/`）：同じ T2・50% の M3 コアの site 1 で、float64 の Jacobi-PCG は 500 回で相対残差 8.8e-7 に止まり、予備実験と同じ現象が再現した。float32 で解いて float64 で直す方法（Jacobi、外側反復 5 回まで）は、外側反復ごとに CG をやり直すため、合計 1,267 回・1.3 秒で 1e-12 に届いた。Kronecker 前処理は、`G` の Kronecker 近似の相対誤差が約 0.7 と大きく、どのサイトでも 1e-2 に届かなかった（使えない）。
3. **ALS の未収束**：どの本も 50 掃引の上限で止まった（掃引ごとの相対減少 1e-6 には届かず、最後の掃引でも 1e-4 前後）。減り方を等比級数で外挿すると、残りの改善は Q_λ の 0.2〜0.6%（T2・50% を M4_retruncated から始めた本は約 5%。T2・25% を M4_retruncated から始めた本は、最後でもまだ減り方が速くなっていた）。未収束は e(M5) を大きめにし、ρ を小さめにするので、判定の向きは変わらない。
   - 追記（2026年11月8日、同じベンチマーク）：M3 から 5 掃引した `Q_λ` は、GPU・float64・Jacobi と、GPU・float32 で解いて float64 で直す・Jacobi の両方で、CPU 版と表示桁まで一致した。合計時間は CPU 版（T1 156 秒、T2 229 秒）に対し、前者が 2.4〜2.7 倍、後者が 17〜20 倍速い。許容誤差を局所勾配で変える方法は 6.5〜20 倍速いが、5 掃引後の `Q_λ` が T2 で 0.04% 大きい。掃引の上限を増やす余地はこの速さで確保できる見込み（50 掃引で数分。推定、未測定）。
4. **初期値への依存**：T2 では、M3 から始めた本が M4_retruncated から始めた本より Q_λ で約 6% 低い（T1 では 0.1〜0.2% の差）。局所解か、収束が遅いだけかは区別できていない。
5. 範囲は、Qwen3-0.6B-Base の layer 14 の `up_proj` だけ、seed は 1 つ。perplexity は 1 層を置き換えたときの小さい差で、区間をつけていない。M4b（AWT）は実装していない（`settings.json` の `m4b_reason`）。
